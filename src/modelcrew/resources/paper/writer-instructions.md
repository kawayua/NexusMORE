# 中文数学建模论文生成约束

本规范优先于历史“数学导出样稿”风格。正文语言为简体中文；数学公式使用 LaTeX。以枢模自编中文建模章节、写作及格式规范和中文研究模板为结构基线；五份资料版本1.0.0，实际路径由workflow 1.3.0指定。当前仅为研究稿，不声称核验了某届官方提交规范。

数学论证库仅用于模型内的公式推导、必要命题证明与公式正确性核对；不得控制论文大纲、标题风格、叙事语言和排版。定义、假设、符号、结果与章节组织由数学建模规范负责。推导围绕题目解释物理/几何含义；较长证明放附录，不将正文写成命题—定理—证明清单。

先输出中文 Markdown 审阅稿，随后等待用户审阅。审阅通过前不生成作为正式论文的 LaTeX/PDF/Word；既有 C+ 编译样稿保留为工程探针，不作为论文默认生成入口。用户批准的是具体稿件 SHA-256；正文或图表修改后原审阅失效。稿件审阅不等于建模方案/结果确认，不改已有双确认规则。

## 写作顺序与内容

正文按“问题重述→问题分析→模型假设→符号说明→模型建立→模型求解→结果分析→误差分析与模型检验→模型评价与推广→结论→参考文献”组织，最后撰写摘要和关键词。摘要交代实际问题、方法、主要真实数值和检验，不堆公式。关键词覆盖方法与题目领域。单题稿只回答指定小题，不冒称完成整道赛题。

建模部分解释选择理由、变量与约束对应的实际意义；求解部分说明算法、分支/停止条件和参数；结果部分用实际表格与图直接回答问题；检验区分模型简化、离散和求根误差，不能只写“效果良好”。模型评价陈述优点、局限和适用范围。正文不含数据库字段、内部状态、哈希、编译日志或审核流程。

图表恢复参考论文手的数量目标：三类候选图各至少 3 张，共至少 9 张；正式入文至少 8 幅，每个子问题三类候选图各至少 1 张且有正式图。单题首稿同样适用。本项目此前“不设固定图数”的默认规划由本次用户要求覆盖。不同文件格式、灰度预览和同图面板不重复计数；缺图必须补齐，不能用空占位符或重复内容凑数。必要流程/建模示意应明确标为示意；数值过程诊断必须来自真实结果，不伪造 solver 迭代轨迹。

每幅正式图有连续中文图号、题注、正文引用和用途，嵌入 Markdown 的实际 PNG 并保留 PDF/SVG。沿用 nature-figure 的真实数据、白底克制配色、最终字号、单位、可读性和审图要求。确定性问题不编造置信区间或误差条。表格含单位并逐一在正文解释。

初稿不强迫达到整题 15000 字/20 页目标；篇幅由单题内容完整性决定。不能把参考技能写作权重、图数、篇幅或年份规则冒称官方要求。用户或当届官方规则需要调整图数时，另存有来源的政策版本，不通过命令行临时减阈值绕过检查。

引用只能来自实际读取的题目、数值方法原文或已核验资料；内部数学包只作证据，不当作外部文献。Markdown 与后续排版共用一份中文正文和图片清单，不得再从数学包自动生成英文证明文章。

## 用户参与选图

提供候选图预览、类别、证据作用、推荐理由和拟放章节，邀请用户保留/替换/合并/要求补图。Markdown 首稿采用暂选图，不代表用户已批准。最终排版要求正文审阅与图片选择均明确通过，绑定同一稿件/图目录/政策哈希；替换图片或改变清单后重新审阅。用户减少数量时需更新政策版本并记录明确理由，不能将算法示意、不同格式或同图裁剪当作新增逻辑图。

## 每次任务的执行入口与时序配图

每次任务先读取 `resources/paper/workflow.json` 指定的文档，而非沿用对话记忆。脚本通过 `modelcrew.modeling_paper.writing_context()` 读取并归档当前正文规范、算法索引、机器政策及绘图要求。项目根 AGENTS.md 固定这条工作约定；通用 Writer 节点也必须加载同一上下文，不可另起一套默认提示词。

遇到运动、形态或几何演化问题，候选图优先考虑题目指定时刻、初始状态、代表性中间状态和终态；用相同总览尺度便于比较，必要时另设局部放大。实物轮廓、长度、宽度、孔位只能来自已核验输入；几何重建和渲染不等于碰撞、受力或实物实验验证。其他题型按证据需求决定，不机械添加位置图。

正文通过后，只增加未入文候选图，且 Markdown 与原入文图字节均不变时，保留该正文的通过记录，继续讨论候选清单。若新图被选入正文、题注变化或文字修改，则生成新审阅版并重新确认受影响部分。最终导出仍要求当前正文与最终图片清单均通过，不能将“正文通过”解释为“全部候选图已通过”。

## 三手协作中的论文手（2026-11-08）

项目业务主 Agent 仅为建模手、代码手、论文手。论文手承担 Writer 职责，从前两手接收版本绑定的模型与真实结果；按 W1/W2 请求未参与其写作的临时独立审查，不通过在同一作者上下文中切换身份完成自审。Validator/Reviewer 不另设常驻业务 Agent。按 workflow.json 加载 docs/three-hand-collaboration.md，具体职责与阶段任务以该文件为准；本文只更新默认规范，不代表通用运行节点已接入。


## E 阶段摘要与分页（用户明确要求）

正式排版前通过 writing_context 实际读取章节模板、写作规范、Word 格式规范、LaTeX 格式规范和中文 main.tex，保存哈希及采用设置的映射。整篇汇编稿应重写为一份统一摘要和一组关键词，不能直接拼接各小题摘要。标题、摘要与关键词应在首页内完整呈现，正文另起第二页；篇幅过长先精炼摘要，不缩小字号硬塞。Word 原生渲染和 LaTeX PDF 均须检查实际分页，字数检查不能代替分页验收。摘要文字修改生成新审阅版本，不覆盖既有通过记录；上述用户要求不等于已核验当届官方规范。


## E 阶段全局符号表（用户明确要求）

整篇汇编论文只设置一个全局“符号说明”章节和一张统一符号表，集中放在模型假设之后、各题模型建立之前；不得按“问题一／问题二”分设符号子表。表中列明符号、含义、单位及适用范围，必要时补充维度、下标或定义域。相同含义且单位一致的符号核对后合并；同名异义或单位冲突必须先明确重命名或作用域映射，并同步更新正文、公式、图表及引用，不能仅凭符号同名自动合并。题目专用符号也收入同一表，用适用范围列区分；模型附近可解释局部新记号，但不得再重复铺设小题符号表。

汇编验收检查仅有一个符号说明章节及一张逻辑符号表、没有按题划分的符号子表，且符号定义与全文保持一致。排版跨页可以续表，不视为多张逻辑表。上游单题材料中的局部符号表用于来源追溯，不直接逐题拼接入全文。涉及符号定义冲突而无法消歧时应停止推进并返回对应来源核实，禁止擅改数学含义。
