# ModelCrew 算法选型与验证补充

版本 1.0.0，2026-11-06。以下为本项目新增观点，不属于复制原文；是方法审查指南，未宣称所有算法或例程均已验证。原文保持字节不变，修订意见在本文件维护。

## 如何使用原资料

先读取[项目索引](index.md)，选择相关类别/章节，再连同本文件对应审查项核对适用条件。优先能解释题目结构、可实现、可验证的简单方法；只有结构、精度或规模需要时才增加复杂度。模型描述研究对象，算法用于求解模型，库 API 是实现接口，三者分别说明。

资料里的“常用”“几乎必用”“秒级”等概括不是选型结论或性能保证。公式、示例阈值、参考文献和示例代码均需结合本题核验，禁止全局忽略 warnings 后把求解失败当成功。不同解法应在相同目标、输入、约束、精度和资源口径下比较，而非只比较漂亮图或单个分数。

## 七类补充审查

| 类别 | ModelCrew 新增审查重点 | 不能直接得出的结论 |
|---|---|---|
| 优化 | 先区分可行/不可行/未证可行/时间耗尽；记录约束残差、目标值、可得的下界与 gap；启发式多种子比较 | 一次运行的最小目标值不等于已证明全局最优，solver success 也不替代约束核验 |
| 预测 | 与朴素/季节基线比较；按时间滚动或按业务分组验证；缺失填补、标准化、特征选择只在训练段拟合；预测区间需校准 | 拟合误差低不等于未来误差低；小样本不自动说明灰色模型适用 |
| 评价 | 核对指标方向、零方差/常数列、相关指标重复计权、权重来源；检查权重扰动及名次反转 | 熵权“客观”不代表业务价值正确，TOPSIS 排名不等于因果优劣 |
| 图论 | 路径/流/匹配先满足业务约束，核对有向性、容量、负边与负环；图规模决定表示与算法 | Dijkstra 不能直接处理负权；最短路不能代替带时窗、容量或多车约束的路径规划 |
| 统计处理 | 先确定观测单位、独立性/配对/重复测量与缺失机制；再选检验；多重比较按检验族设计；报告效应量与区间 | 正态性检验通过不证明独立性；不显著不证明等价；相关不证明因果 |
| 综合/仿真 | 明确随机机制、初边值、离散化及有效域；区分蒙特卡洛误差、数值误差、参数和模型不确定性 | 增加采样次数不会消除模型偏差；有限实验不能当理论收敛证明 |
| 机器学习 | 使用匹配业务损失的指标、分层或分组验证、类不平衡处理、校准与成本记录；同一实体不得跨集合泄漏 | 单次随机划分高分不代表泛化；标准化应取决于方法，不能所有模型机械套用 |

## 当前题目需要的扩展

现有几何/运动题优先读取[几何约束、求根与数值验证](numerical-geometry.md)，再视问题加载综合类、优化类资料。弧长参数化、约束方程、连续选根与误差预算必须从题目和原理建立，不以常见优化算法替代物理/几何建模。

原优化资料的线性规划“单纯形搜索路径”图用硬编码顶点绘制，不是求解器实际轨迹。采用其代码时应标注示意，或用真实 solver 日志产生过程图，不能作为本次运行证据。原资料中的通用参考文献表也不等于元数据已经核验。

## 与数学论证和绘图交接

选法后由 math-reasoning 能力建立变量域、符号/单位、假设、关键推导和验证计划，形成 MathematicalDossier 草案；其 Schema、角色自动生成和审查仍待实现。先有定义与成立条件，再写公式；区分引用定理、本题推导、数值验证与经验观察。Writer 复用同一数学源，不重新编造推导。

图只用于呈现真实数据、诊断与结果，具体遵循[科研绘图规范](../../docs/scientific-figure-contract.md)。每种方法先定义可验证结论，再决定图型；无实际迭代轨迹时不伪造收敛曲线。示例代码迁入后仍经契约确认、审阅和受控执行，复制文档不授权自动运行其中代码。
