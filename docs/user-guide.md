# 使用指南

枢模 · NexusMORE 的日常入口是 DSH 原生会话。安装与接入命令见 [README](../README.md)；本页说明安装后的实际操作。当前仅有已记录的本地 Windows / DSH 实测通过范围，新设备在开源后由用户补测，见[兼容说明](compatibility.md)。

## 工作区与配置

将源码/安装环境和业务工作区分开。默认用户工作区为 `%LOCALAPPDATA%\NexusMORE\workspace`，也可在启动命令和宿主注册前用 `MODELCREW_WORKSPACE` 指向自己的目录。始终使用注册时选定的同一个 CPython 3.13 环境；修改工作区或 Python 路径后，先核对现有注册，不直接复制旧机器路径。

| 位置 | 用途 |
|---|---|
| `configs/local/settings.json` | 模型名称/端点、路径、执行器与导出设置；只保存密钥变量名 |
| `configs/local/secrets.env` | 实际模型密钥、数据库连接等秘密；只在本机保管 |
| `configs/local/runtime/` | 通过准备包安装时的独立 Python/原生工具；源码 venv 不位于此处 |
| `runs/` 及已登记产物目录 | 输入绑定、运行/质检/恢复证据和产物；具体位置以工作区设置和业务回执为准 |

源码检出有开发默认路径，安装包有用户目录默认路径；显式工作区最容易避免连错数据库或找不到旧任务。`init` 保留已有配置，`config-show` 仅给脱敏摘要，不能代替手动核对模型选择。详细字段与环境变量见[用户配置](user-configuration.md)。

密钥必须由用户在本机填写，不放进聊天、Git、DSH 插件 YAML 或 issue。模型调用会发送相应任务/证据给所配服务；使用私有材料前确认自己有权使用并接受该服务的数据处理方式。普通 Chat Completions 兼容不自动等于所有结构化/图片接口兼容。

## 准备运行条件

README 的安装/初始化步骤完成后，`environment setup` 创建工作区独立服务、执行器和文档工具；`workflow_mcp migrate` 补齐当前业务迁移；`doctor --profile workflow --services` 做只读配置与服务诊断。它们不会批准方案或替用户发起真实建模。

默认算法检索从包内索引按名称/ID/类别读取，不要求外部技能包、BGE 或算法 Qdrant 集合。需要论文语义检索时，另按[环境准备](environment-preparation.md)配置本地权重、Qdrant 和论文索引；部署探针里的合成段落不等于已接入真实论文库。正式导出使用 Tectonic 0.17.0、Pandoc 3.6.4；Word 原生渲染另需 Microsoft Word 和实际使用的中文字体。

## 在 DSH 开始研究

打开已接入的 DSH profile，运行 `/nexusmore`，检查工具注册及后端读取状态。它是连接检查，不会消耗一次建模任务，也不能证明模型服务和所有科学工具已通过。连接问题见[排错指南](troubleshooting.md)。

在新会话附上题面和所需数据，明确要处理的小题、单位、强制输出、允许使用的外部资料和已有方案。先请枢模列出缺项和建模方案。原题包含多小题时，明确本轮范围和跨题依赖；只完成问题一的记录不扩大为整套题完成。

| 阶段 | 用户需要查看/决定 | 系统后续行为 |
|---|---|---|
| 方案讨论 | 输入是否完整、假设/算法/检验口径是否符合研究目标 | 建模手完善资料，独立 M1 检查；待方案可审后展示当前版本 |
| 方案确认 | 打开当前完整方案，明确通过或提出修改 | 确认绑定该版本后才进入相应求解流程 |
| 求解与结果 | 查看带单位表格、代表图、全部文件链接、误差及独立检查状态 | 代码手执行与检验；结果待确认，不把可运行等同正确 |
| 结果确认 | 决定当前结果可否用于写作，单独处理实际披露的偏差 | 进入中文 Markdown 写作与审查 |
| 正文与配图 | 阅读合并页完整正文及全部候选图，核对暂列入文图 | 同一写作 run/build、同一版本的一次确认原子记录正文和暂列配图批准 |
| 正式汇编与导出 | 查看实际导出、全页检查和独立 W2 后的正式成品 | 用户最终审阅；前面的正文确认不等于最终排版批准 |

质检节点是 M1/P1/P2/W1/W2，由独立上下文审查当前证据；系统内部通过记录不替代需要用户作出的决定。默认研究论文候选图为三类各至少3张、合计至少9张，正式入文至少8幅；题目/用户明确调整时另外记录。全篇使用一个全局符号表。小样例不交付论文，不能拿它的轻量检查代替研究论文要求。

## 如何确认或要求修改

先打开宿主回复所附的当前审阅文件，再在原会话明确回复“通过”或页面支持的明确确认语句。正文和配图共用合并审阅时，一次决定只覆盖当前正文与当前暂列入文图。要换图、改公式或改结论，先提出具体修改，等新版展示后再确认。

“是否通过”“通过但先修改第二条”等疑问或带修改条件的句子不是批准。模型写出的“用户已同意”、DSH 工具权限弹窗、脚本里的 `actor=user` 也不是批准证据。没有展示当前稿、稿件已变更或对象不唯一时，系统应要求重新定位并展示，不追溯使用旧消息签字。当前原生展示与可信捕获边界见[对话审阅说明](dsh-chat-review.md)。

自定精度未达标时，先看实际误差、单位、时空位置、影响与改进成本，再决定继续计算还是接受限定偏差。接受偏差保留原阈值 FAIL，且不等于同时批准模型、结果、论文或其他检查。显示小数位数本身不说明数值准确度。

## 读取产物、继续与恢复

日常从 DSH 回复里的文件链接打开方案、结果、合并审阅稿或正式文件，具体文件位置以当前任务回执为准。不要直接改已登记正文、图或证据文件；需要调整时走修订流程生成新版本，以免原哈希绑定失效。复制文件用于个人阅读不产生新批准。

中断后重开原会话，先读取原任务状态与回执，再继续同一任务；使用原生右侧下一题入口创建独立小题，保留可追溯跨题引用。重启不会自动使失败变通过，也不应反复新建项目来绕过原失败。会话协调与导航见[连续会话说明](dsh-conversation-workspace.md)。

如返回 `outcome_unknown`，要求查询原请求的 `operation_status` 并对账；不要换幂等键重复求解或再次提交决定。响应已收到但格式/证据引用非法，按内容问题处理，不当成未送达。复核每个 attempt 最多一次，恢复不重置作者预算。具体诊断入口见[排错指南](troubleshooting.md)。

## 使用范围与后续测试

本地完整业务的实际证据沿用 [G5 报告](validation/g5-acceptance-20261119.md)，包括其单题覆盖、已接受偏差和已知限制。用户已决定先完成文档及后续首发准备，干净设备在开源后自己试用；这项延期不是通过记录。本轮不报告留出题求解率、机制对照优势或其他宿主兼容结论。使用中发现问题可按[贡献指南](contributing.md)提供脱敏复现材料。
