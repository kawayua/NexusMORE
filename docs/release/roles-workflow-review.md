## 必须调整的冲突与缺口

**用户确认与不可变版本。** 上游 `建模手/references/工作流程.md:67` 要求直接修订已有两个文件，且不创建同义版本文件；枢模需生成新版本与受影响复验，保留旧批准。上游模型合同嵌在分析报告中，枢模需保留独立的版本化契约/数学材料及任务、结果绑定。M1/P2 通过仍不能代替用户模型/结果确认。

**写作交付顺序。** 上游导航和论文手入口默认直接交 Word；论文手工作流程第 5 行写默认只交 Word，第 94 行又列默认 Word 与 LaTeX/PDF，存在内部冲突。枢模以 W1 → 中文 Markdown → 正文与选图分别确认 → 正式导出/W2 为准。所有宿主读取同一项目规范，不各自维护不同提示词或默认流程。

**规则与方法依据。** 每题最多两个模型、关键/可放宽假设条数、摘要四段或五段、15000 字/20 页、竞赛题型和评分权重不能未经取舍就变成产品硬规则。尤其 `写作规范.md:16` 的评分比例、摘要占比没有在该文件提供可核验依据，不作为官方事实或稳定产品默认。引用到的年份、页数、赛题分类仅登记为来源声称，实际任务再核验当届官方材料；本轮没有检索确认当前竞赛规则。枢模已有九张候选/八幅正式图要求来自项目政策，继续依当前用户要求执行。

**求解不能自行改变已确认方案。** 上游代码流程第 58 行附近允许超时后精确→启发式、全量→抽样等降级。枢模需先核对已确认合同；涉及模型、目标、精度口径或验收范围变化时回到建模修订和用户确认。数值阈值、归一化/正则化、全零输入输出判定也应有模型依据，不能一律照搬。

**工具脚本不是运行接入。** 8 个辅助脚本仅静态阅读，没有导入或执行。`plot_style.py` 是旧兼容层，用外部技能目录标记识别根路径；`repro_manifest.py` 用固定父目录推导根，且有覆盖开关。`figure_audit.py` 不带 `--strict` 时即使报告 FAIL 也可能退出 0，仅审 SVG/PNG，不能替代项目 PDF、哈希、图意和版面检查。应合并功能目标与现有项目机制，授权或独立实现后再接入，而非原样复制到任务目录。MATLAB 工具箱检查不证明许可/运行可用；当前 Python 运行能力不等于支持 MATLAB。公式重算、通用转换及正式导出依旧按后续任务接入。

**论文模板与全局符号。** Word 模板仅只读 ZIP/XML 检查，包含示例/占位文字；观察到的符号列为符号、说明、单位，缺枢模要求的适用范围。没有核验它是官方模板，没有渲染、验证最终页数或批准使用。后续授权或自行重建时遵守一篇一张全局符号表、模型假设之后/各题模型之前、符号冲突显式映射，不能按小题分表。英文工作流作为可选能力保留，不覆盖默认中文。

**截止时间与恢复。** 保留带时区的截止依据、缓冲、独立检查点和人工提交确认；紧急交付不绕过用户批准、独立审查或已核验硬约束。后续应与项目暂停恢复、未知调用只查状态及返工预算联动；不能把一个文档协议登记为运行实现。
