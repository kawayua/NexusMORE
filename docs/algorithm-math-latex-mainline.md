## 核心交付标准

系统应完成“理解问题结构 → 按适用条件比较方法 → 建立数学模型 → 给出有依据的推导 → 实现并验证 → 用论文级数学语言和 LaTeX 表达”。数学论证从建模时产生，Writer 沿用已审查的数学内容，并结合已确认结果形成论证完整的章节。

这里的论文级严谨表达包括：符号先定义且全文一致；变量有定义域、维度和单位；事实、假设与结论分开；推导交代条件和依据；目标、约束与边界完整；公式有稳定编号并在正文引用；结论限定适用范围；统计结论有适用前提、区间和效应量；引用可核验。排版可编译是必要条件，不能代替上述数学检查。数值实验验证、经验观察与形式证明必须区分。

## 按题目选择方法

以 math-modeling 的七类算法为资料入口，按题目的目标、数据、结构和约束选择方法，不按题号、比赛标签或关键词直接绑定算法。分类允许组合；同一问题可采用不同解法，但每种选择均需说明理由。

| 问题结构 | 可考虑的模型/解法（不是固定答案） | 选择前要核对 | 必须提供的验证 |
|---|---|---|---|
| 连续几何、运动、物理机制 | 几何约束、代数方程求根、积分、常/偏微分方程 | 状态定义、坐标、单位、初边值、存在性和解的分支 | 守恒或几何残差、边界/退化情形、步长或精度敏感性 |
| 资源分配、调度、路径决策 | LP/MILP、动态规划、约束非线性优化；必要时启发式 | 变量离散/连续、线性/凸性、规模、可行性、计算预算 | 约束残差、求解状态；可得时报告界或 gap，启发式报告稳定性 |
| 趋势与时间预测 | 朴素/季节基线、回归、指数平滑、ARIMA；有需要再引入学习模型 | 时间依赖、趋势/季节、外生变量、样本量、漂移和可用预测信息 | 时间顺序回测、基线、误差和预测区间，避免数据泄漏 |
| 多指标评价与排序 | AHP、熵权、TOPSIS、DEA 或其他与任务匹配的方法 | 指标方向、尺度、相关性、权重来源及评价含义 | 一致性或适用性检查、权重/排名稳定性，不能把排序当因果 |
| 图结构与网络 | 最短路、流、匹配、生成树等 | 有向性、权重符号、连通性、容量及业务目标 | 路径/流/匹配合法性、可行性和适用的最优性依据 |
| 数据解释与统计推断 | 回归、检验、降维、聚类及适用的稳健方法 | 抽样单位、独立/配对/重复测量、缺失机制、分布与混杂 | 效应量、区间、诊断和必要的多重比较控制；描述/预测/因果分开 |
| 随机系统、分类与复杂仿真 | 蒙特卡洛、随机过程、系统仿真；分类/集成学习等 | 随机机制、标签、类别不均衡、训练信息边界和资源需求 | 多次运行与收敛；分类使用适配指标、训练/测试隔离及基线 |

七类资料仍保留原目录标签；上表按任务结构重组，连续机制类补充来自可核验的几何、求根、数值分析与领域文献。资料没有覆盖时明确缺口，不能为了命中卡片强行改题。

形成 `MethodSelection` 逻辑记录：问题指纹、候选方法、适用条件核对、所需数据、选择理由、未选理由、来源、模型与求解器的区别、复杂度、验证办法及失败后的替代路径。候选比较按有意义的差异进行：不为了凑数机械提出两种模型，也不默认复杂模型更好。方法推荐分数只用于排序，不能作为数学成立的概率。

## 数学论证包与统一来源

`MathematicalDossier`（数学论证包）已在B+发布1.0.0 Schema，并由MathematicalPackage绑定方法选择与原契约；详见[正式交接说明](mathematical-handoff.md)。以下列出逻辑职责，计算后结果通过既有结果/执行记录及确认快照关联，不回写冻结包。它与契约、执行产物分别存储并做版本绑定，复用同一套符号和公式标识。

| 内容 | 最低要求 | 主要责任 |
|---|---|---|
| problem setting | 输入、目标/待计算量、变量域、数据结构与单位 | Modeler |
| notation | symbol_id、含义、LaTeX 表达、单位、维度、作用域、首次定义位置 | Modeler，Writer 复用 |
| assumptions | assumption_id、内容、来源/理由、适用范围与影响 | Modeler |
| equations | equation_id、LaTeX、符号引用、假设引用、意义和来源 | Modeler |
| derivations | 前提→中间步骤→结论，每步依据、适用条件、待补缺口 | Modeler，Validator 审查 |
| propositions / proofs | 需要时给命题、前提、证明/引理来源；否则说明不适用 | Modeler，Validator 审查 |
| validation plan | 约束/量纲/边界、误差、稳定性或统计检查及验收依据 | Modeler/Reviewer |
| result claims | 计算后才增加：结果版本、数值证据、单位、适用范围和不确定性 | Reviewer，Writer 复用 |

采用 math-reasoning 的 formalize、derive、verify、notation 作为基本能力；stats 与 prove 按题目需要启用。不强迫每道题都写定理或显著性检验。每条关键结论注明证据类型：题面给定、明确假设、外部定理、本题推导、数值验证或经验观察。未完成证明的内容不能写成已证定理，数值收敛不能替代理论收敛证明。

契约负责可执行规格，论证包负责解释规格的数学含义与成立依据。两者通过稳定 ID 绑定，避免两份独立手写公式逐渐漂移。所有公式保留可读的 LaTeX 源和结构化符号引用，不直接 eval，也不以编译器代替数学审查。解析不了的公式记为需审阅，不降级为已验证文本。

## A/B/C 增补安排

历史 A/B/C 保持已验收状态；新增 A+、B+、C+ 作为同一项目中的增补工作包，各自保存新证据。可以沿用现有任务和上下文，涉及模型、输入、代码或已确认解释的变化时按既有规则创建新版本并重新确认。只有独立新增记录通过检查，才能宣称新增质量标准已具备。

| 增补包 | 要做的工作 | 新增验收依据 |
|---|---|---|
| A+ 因题选法与数学基线 | 为现有小题提取目标、数据、几何/物理结构和约束；读取相关算法原文，形成方法取舍和数学论证草稿；补一个结构不同的小样例检验推荐行为 | 现有题可解释“为何这样建模、为何用此算法”；另一题结构产生适配的推荐或明确缺口，不机械复用旧解法；关键定义、推导、量纲与边界能核对 |
| B+ 数学交接与确认 | 定义方法选择及数学论证包的版本契约、符号/公式/假设 ID；向用户展示可读数学提案；定义数学变更与纯排版变更的失效规则 | 同版本契约、数学包和用户确认能绑定；数学变更不能沿用旧确认；旧 Schema 与旧哈希保持有效；渲染文本与结构化含义一致 |
| C+ 算法检索与数学导出 | 建立按适用条件检索的最小算法资料集；保留公式/前提/代码/文献的语义边界；用真实数学包导出最小 LaTeX/PDF 并回溯证据 | 查询可返回原文位置、卡片版本和适用限制；数学片段未被截断成缺条件公式；真实编译、引用解析与渲染检查有证据，数学正确性另行审查 |

建议顺序：A+ 定义问题和数学质量样例 → B+ 固化交接/变更规则 → C+ 验证资料检索与最小数学导出 → D 接入真实角色并在多小题推广 → E 全文汇编 → F 评测。增补不要求从零重建已有数据库、MCP、沙箱或工作流。

A+ 的不同结构小样例用于方法适配检查，不扩张为完整赛题评测；不要求这两个例子一定使用不同算法，同一算法在适用条件相同的情况下允许复用。推荐对照至少含一个适用和一个前提不满足的情况，核对系统能解释拒绝理由或缺口。方法比较与数学审查先作为单流程能力实现，角色拆分在 D 完成。

## LaTeX 提前到什么程度

A+ 就生成符号、定义、假设、关键公式与推导的可复用 LaTeX 片段；B+ 把这些片段及其语义标识绑定版本；C+ 对最小数学稿真实编译并查看 PDF。计算结果缺失时只形成数学规格/方法说明，不生成带虚构结果的论文。结果确认后的 D/E 才形成完整的结果章节和总论文。

长篇论文使用同一套数学包和确认后的结果，结构包括问题形式化、假设与符号、模型建立、关键推导、求解算法、验证、结果和局限。Writer 可以改善论证顺序和语言，但不能为排版便利改动条件、公式或结论。新增推导/命题回 Modeler 与 Validator，关键数值回 Reviewer 核验。

验收分为三层：结构检查（ID、符号引用、编号、来源）；数学审查（定义、推导、假设、量纲、边界与适用性）；导出检查（真实编译、未解析引用、字体/公式、版面与 PDF 渲染）。每层单独报告 PASS/FAIL/BLOCKED 与覆盖范围；不因另两层通过而省略一层。保存 .tex 源码、构建命令、日志、引擎版本、资源清单和 PDF 哈希；首个可用版本保留。

## 变更与回归边界

数学变化包括假设、变量域、公式、边界、算法选择、容差或检验口径变化，需审查其下游影响，必要时新契约、重算、重确认。只改 LaTeX 空白、行距等不改变含义的版式，可保留执行和用户确认，重新编译/渲染；符号重命名只有在语义映射等价经核查后才按表示变化处理。不得自动把所有公式编辑归为排版变化。

首轮验收重点是已有几何/运动题与一个结构不同的小样例、结构合法但数学错误的反例、算法前提不满足、符号未定义或单位冲突、推导缺条件、旧版确认失效、公式缺失和引用编译失败。用这些证据评估是否会选法、是否能严谨表述，不能只展示一份看起来专业的 PDF。
