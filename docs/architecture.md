# 架构

枢模分为DSH宿主适配、Python共享业务核心、受控执行与证据层。宿主展示文件和转交真实用户消息，核心管理版本、路由、审批校验和恢复；PostgreSQL与业务登记是状态依据。

| 职责 | 工作 | 实现入口 |
|---|---|---|
| 建模手 | 问题拆解、资料、假设、算法与数学论证 | `modeling_hand.py`、`modeling_proposal.py` |
| 代码手 | 最小求解、完整计算、检验与图表 | `hand_runtime.py`、`docker_executor.py` |
| 论文手 | 已确认结果的中文正文、修订与汇编 | `hand_runtime.py`、`modeling_paper.py`、`writing_handoff.py` |
| 独立质检 | M1/P1/P2/W1/W2节点的独立上下文审查 | 当前快照、派发与回执校验 |
| 程序编排 | 资料冻结、版本、幂等、暂停恢复 | `workflow.py`、`business_store.py`、`assembly_builds.py` |

这些是职责，不增加总指挥Agent或常驻第四角色。作者自检、独立审查和用户批准不能相互替代。

## 业务与宿主

`src/harness/`保存项目自编宿主JS，安装副本位于`src/modelcrew/resources/harness/`，两者需同步。`dsh_integration.py`负责操作者注册与回退，`workflow_mcp.py`提供stdio工具入口，`business_adapter.py`映射到既有业务服务，不另建一套宿主工作流状态。

当前MCP开放40项模型通道工具。契约中的未开放操作不会因文件存在或提示词声明就变为可用。真实用户决定经宿主消息、展示内容和版本绑定，在后端再次验证；旧维护入口中的actor字段不是身份凭证。

## 资源与执行

随包资料通过资源API读取，按角色、阶段与任务类型选择，冻结内容哈希。文件被打包与能力实际运行是不同证据。默认算法字面查询与需另行部署的论文向量检索分别处理。

模型生成的Python在受控Docker任务中执行，不在宿主直接导入。运行、数值检验、全页审图、正式导出与用户确认分别记录，错误按影响返回对应阶段。

## 版本与恢复

修改操作绑定请求、对象版本与证据身份，重复请求复用原回执。执行未知先只读查询；已收到但结构/引用非法的响应不当作未送达。修订生成新版本，保留原失败和限定偏差接受。

同一run/build与版本的正文/配图可以合并确认，后台原子记录两个范围。正式导出使用批准内容源，完整PDF检查和独立W2继续执行。当前是本地单用户架构，不是面向公网的多租户认证系统。

操作见[使用指南](user-guide.md)，边界见[兼容说明](compatibility.md)。
