# E 之后：开源 Agent 与 harness 接入路线

更新：2026-11-10。用户最终目标是可供他人安装使用、可由外部 harness 引入的数学建模 Agent。用户已说明 E 阶段全部完成；本计划据此推进后续，不重写 E 历史验收材料或代签其他批准。以下 F/G/H 均为待实施任务，本次只更新路线。

## 交付定位与架构

交付 枢模 · NexusMORE 核心运行时、完整工作流的对外适配层、可分发资源及安装说明。内部保留三手＋独立质检、版本绑定、跨题引用、显式用户确认与恢复、中文 Markdown 先审阅和选图、全局统一符号表与确认后正式导出。harness 负责调用和呈现交互，核心运行时维护业务状态；不要求 harness 重新实现三手编排。

现有 paper-search/code-executor MCP 是内部能力服务，不是完整业务 Agent 入口。计划增加面向完整工作流的 MCP 适配层，复用已有 Workflow/HTTP/CLI 业务实现，避免另建状态源。首版以本地单用户和 stdio MCP 为范围；不把面向公网的多租户、安全认证和全平台支持列为首发前提，也不宣称任何 harness 都无需适配。

## F：安装分发与可移植运行

| 子任务 | 实施内容 | 验收条件 |
|---|---|---|
| F1 发布范围与资源清单 | 确定首发系统/Python版本、模型服务接口、功能边界；区分代码、模板、算法资料、模型权重及用户输入 | 发布清单不包含密钥、真实私有题目、不可分发材料或仅本机存在的必要依赖；现有功能与局限明确 |
| F2 统一安装包 | 建立 pyproject、包版本、CLI入口、核心/检索/论文导出等可选依赖组；打包 contracts/resources/migrations 所需资源 | 构建 wheel/sdist，离开源码目录安装后仍可定位资源与启动；不能依赖仓库父目录计算运行资源路径 |
| F3 用户配置与初始化 | 统一模型/数据库/检索/执行/导出配置、数据目录与环境检查，提供示例和初始化命令；写数据不落安装目录 | 新用户用自己的密钥和资料启动，无开发机绝对路径；缺依赖明确报告，不静默换模型或伪造输出 |
| F4 服务部署与干净环境 | 复用并整理 PostgreSQL/Qdrant/Docker执行器部署、迁移、检索初始化与文档工具链；提供最小样例 | 新环境按 Quickstart 初始化、运行、停在确认点、重启恢复；记录实际平台和首次联网下载需求 |
| F5 依赖许可处理 | 选择项目代码许可证，逐项确认第三方资料/模板许可并记录归属；许可未明的资料不纳入公开发行 | 顶层 LICENSE、第三方清单和发布资源一致；获许可后纳入，或改为用户自备/可分发的独立编写替代；不得将工具子目录许可证套用到算法正文 |

现有复制算法资料的 provenance 已注明再分发许可未确认，F5 必须实际解决。用户授权本地复制不等于获得第三方开源许可。不得为修复发布包直接删除本机历史参考资料；用发行清单区分本地研究材料和可发布资源。

F 完成意味着可以安装和本地使用，不等于已发布，也不等于已接通 harness。F1 先明确首个目标 harness 的名称与版本，G 才能给出可核验的兼容性声明；当前尚未指定具体宿主。

## G：完整 Agent 接入 harness

| 子任务 | 实施内容 | 验收条件 |
|---|---|---|
| G1 冻结业务工具契约 | 定义创建项目/导入题目、启动/推进、查询状态、读取待确认项、提交用户决定、修改/恢复、列出/读取产物；冻结版本/幂等/错误语义 | 契约映射到已有业务服务，标明已实现/缺失操作，不仅暴露底层检索和执行 |
| G2 完整工作流 MCP | 选择兼容传输与协议版本；实现标准输入输出工具入口，结构化回执、状态和可读取产物；日志不污染 stdio 协议 | 标准 MCP 客户端可发现并调用；重发/断连不重复求解，未知执行先查询，数据库仍为事实来源 |
| G3 确认和身份边界 | 返回 needs_user_input 与明确版本、待确认内容，宿主展示给用户；宿主将真实用户决定转交服务 | 模型工具调用本身不是用户批准；actor字符串或提示词不当作身份认证；本地可信适配与可核验用户事件边界写明并实测 |
| G4 宿主配置示例 | 对首个选定 harness 提供安装、配置、启动和排错示例；Skill/提示词入口仅作可选便利层 | 在真实外部宿主调用 枢模 · NexusMORE，保留宿主版本与工具记录；不是只在开发脚本中直调 Python |
| G5 接入故障与交互验证 | 覆盖重复调用、过期确认、任务恢复、工具故障、产物路径边界及正文/选图分别确认 | 客户端断开后恢复同任务，无误批准、无数据串题、无重复执行；宿主能继续确认与读取产物 |

不能假设所有 harness 都支持同样的确认界面。若宿主不能可靠承接真实用户决定，使用本地CLI或现有可信交互入口完成确认，MCP只读待办/状态；不得取消人工关卡以获得“一键成功”。

## H：跨环境评测与开源首发验收

| 子任务 | 实施内容 | 验收条件 |
|---|---|---|
| H1 两级验证数据 | 可公开小样例验证安装/接入；完整研究赛题验证业务质量；开发集与留出集分开，记录外部资料暴露 | 启动联调/固定样例不混入真实LLM求解率；对外样例许可明确，完整试题覆盖范围如实说明 |
| H2 宿主端到端验收 | 从干净环境通过首个 harness 完成题目→方案确认→运行→结果确认→中文MD→正文/选图确认→正式汇编导出 | 冻结候选发行版本；不用开发机私有缓存或历史工件冒充新运行，源/模型/依赖/成本和失败均可追溯 |
| H3 机制评测 | 保留原F有/无契约核心对照，再按预算增加独立质检、用户指导及算法卡片对照；记录成本和统一外部评分 | 各组配置、信息、预算、分母可核验；不让自己Reviewer评分成为唯一效果证明；七Agent对照可选 |
| H4 使用文档与贡献 | 重写README为Quickstart，历史研究报告归档导航；架构、兼容表、故障指南、贡献说明、问题模板、变更记录和自动检查 | 首次使用者无需阅读阶段日志即可安装使用；贡献者可运行不需要私密数据的必要检查 |
| H5 首发准备与最终动作 | 生成版本化发行包、依赖/许可清单、实测说明与已知限制；复核敏感材料和包内容 | 完成可审阅发行候选；推送公开仓库、上传包仓库和发布release等外部发布动作需对应明确授权，不因本次改计划自动发布 |

原 F 的 Gradio 可以作为可选本地界面，不应成为 harness 接入的前置条件；简历和演示资料从实测证据汇总，移到 H 收尾，不占产品主线。原固定模型/提示词/工具预算、来源泄漏控制、失败分类、恢复与定向重跑评测要求全部保留。

## 推进顺序与完成定义

先 F1/F5 识别许可和发行范围，同时推进 F2/F3；F4 验证可移植安装后开展 G。H1 的小样例和测试可提前编写，H2/H5 针对冻结发行候选收口。不要先扩展大量前端、多宿主或题库，再补最基本的安装和完整工具入口。

首发最低交付：一个明确支持的安装环境、一个实际验证的 harness、可分发的最小算法/模板资源、真实用户确认通道、版本与重启恢复、完整研究稿导出和可公开的样例。达到这些条件可表述为“可开源分发、已在所列环境与宿主验证”，不表述为“任何人任何平台开箱即用”。

本次路线更新没有安装新依赖、创建MCP服务、选择代码许可证、重跑收费实验或执行外部发布。E成果继续复用，不重开求解与论文批准。
