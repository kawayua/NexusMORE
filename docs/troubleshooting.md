# 排错指南

先确认Python、工作区和DSH profile，再读取原状态；保留原失败与回执。公开报错前清除密钥、连接串、私有题面、个人路径和原始聊天。

| 现象 | 处理方式 |
|---|---|
| Python或包找不到 | 使用实际CPython 3.13和同一venv的`python -m pip`，不使用DSH附带3.12；安装后运行`pip check` |
| 诊断通过但业务仍失败 | core只检查基础项；用`doctor --profile workflow --services`核对业务条件，文档/检索另按实际依赖准备 |
| API拒绝参数 | 核对具体端点与模型、结构化输出和thinking扩展参数；保留原错误，不自动切供应商 |
| 终端有密钥而DSH没有 | 宿主可能清理继承变量；按配置将秘密保存在对应工作区的`secrets.env`，不要写入插件YAML |
| Docker不可用 | 分别检查Desktop、WSL2、Linux引擎和当前进程命名管道权限；终端可访问不代表所有受限进程可访问 |
| 数据库读取失败 | 用同一工作区执行`environment status`，核对归属与配置；操作者确认后补充迁移，不删卷重置 |
| `/nexusmore`未出现 | 核对实际profile和插件active状态，完整退出DSH再打开 |
| 注册器拒绝覆盖 | 核对管理块、备份、锁及后续修改；不删除管理块盲重装 |
| 缺科学依赖或中文字体 | 在任务执行前准备对应镜像/工具；容器任务禁网，不在求解中临时安装 |
| `outcome_unknown` | 查询原请求状态和回执，不换请求键重复执行 |
| 响应已收到但JSON/Pointer无效 | 按结构或证据问题处理，不套用未送达恢复 |
| 无待审稿或稿件已变 | 重新定位并展示当前完整稿后确认，旧文字不补签 |
| 小题无待办但汇编待审 | 定位实际引用该题的唯一有效汇编，不把小题结束解释成项目无待办 |
| Word或LaTeX导出失败 | 核对批准内容源、支持工具、字体及Word权限；编译成功、预览生成与独立质检分别记录 |

保留完整PDF页数与逐页检查，不隐藏警告或删页换取通过。每attempt独立复核最多一次，不通过反复请求清空失败。

具体操作见[使用指南](user-guide.md)、[环境准备](environment-preparation.md)和[DSH接入](dsh-local-connection.md)。提交问题使用[缺陷模板](../.github/ISSUE_TEMPLATE/bug_report.md)，优先提供原创小输入复现，原始证据在本机保留。
