## 共享入口与范围

入口是 `modelcrew.resource_routing`；CLI 为 `modelcrew route --request request.json --input-root INPUTS --output ROUTES`，`--plan-only` 只做实际资料读取和计划落盘，不执行工具。各 Harness 后续复用同一入口，不新增常驻调度 Agent。不安装或查找外部技能目录，不在业务运行期间下载替换资料或临时安装依赖。

包内 `capabilities/routing.json` 注册角色/阶段、格式、依赖、资源和限额。首版执行范围为 PDF 全页文本读取、XLSX 全量单元格读取、DOCX 结构检查。PDF 不做 OCR，也不据文本读取声称视觉通过；表格保留公式字符串，不声称重算；Word 检查不替代渲染或 W2。正式导出、任意代码执行、修订接受和用户批准不在此路由注册范围。

注册工具为可信 Python 适配器，通过当前安装的 Python 子进程执行；`-I` 禁止从当前目录加载模块，显式提供本项目包位置及已声明依赖的安装位置。兼容用户级 Python 安装依赖，但要求导入来源位于对应 distribution 的安装目录。原附件复制到私有输入目录；结果、日志、退出码、输入/输出摘要和目录映射保存到回执。建模求解仍走现有 Docker Linux 执行器，本入口不在宿主执行模型生成代码，也不借文档工具扩大执行权限。

## 自动选择与实际读取

先读取包内算法索引，再按问题词、规范算法 ID 和类别选最多 3 个算法节；按需读取最多 3 个数学专题。首版是确定性匹配与模型建议经程序校验，不是通用语义分类器，也不为无匹配题目强套算法。自然语言前提保持未知，选中资料不代表已采用方法或得到可行/最优证明。

论文手额外实际读取项目中文论文工作流、写作与配图政策及规定模板；数学资料只约束公式、论证和核对，不取代中文数学建模体裁。根据附件类型，实际读取对应包内 SKILL 指南及所需参考；指南和附件内容在模型输入中仅作为资料，不能覆盖程序冻结的本地规范。

F6 联调发现旧运行目录的六卡片目录仍绑定较早算法索引。新建模任务已改为包内规范七类目录与项目自编几何补充，不再依赖开发机的旧运行目录或旧索引配置。旧卡片文件、配置、原始来源及哈希原样保留；既有向量检索 MCP 路径不冒称已经重建为全 113 算法语义索引。新的模型规划可导航规范算法 ID，按当前类别读取对应节；几何任务保留本地连续异号括区间等参考及其前提判断。

每次选择记录来源路径、完整源文件 SHA256、实际读入文本的 SHA256、读取范围和选择理由。工具完整输出留档；过大输出不直接塞入模型上下文，明确返回“未完整包含在上下文”和对应产物哈希，不能把省略内容说成已提供给模型。

## 任务绑定、幂等与恢复

请求必须绑定 task_id、question_id、version、role、stage、request_id、contract_sha256 和 query；这些标签是范围和审计字段，不是认证或业务批准。输入路径限指定 input-root 内的相对路径；重复文件、越界、链接、未知格式、未知方法及角色/阶段不匹配均明确拒绝。单附件 8 MiB，最多 8 个；资料文本上下文限 200 KB。需要更大资料或其他格式时，先扩大已审范围或准备受支持副本。

程序在调用前落盘 claimed 状态。重复键改变查询、附件、契约或计划会冲突；同一请求完成后只读已保存回执并复核产物。资源更换要求新请求，原记录保留。已保存的全部完成回执可直接恢复完成；仅有不完整父回执时只查询 worker 已有结果，返回 outcome_unknown，不重派发。默认自动重试为 0，失败修复后使用新请求，不无限重试或静默换工具。

新代码手/论文手在现有权限检查后冻结 `resource-routing.json`，模型作者调用读取实际资料和文档结果，并记录当前阶段的使用绑定。新建模规划和每轮方案分别绑定当时契约及版本。旧运行没有该标记则保持原输入形态，不自动补写或追改历史模型上下文。

独立 M1/P1/P2/W1/W2 继续由原节点建立只读证据快照，不注入作者私有路由历史或会话；独立角色不能通过本入口执行附件工具。程序路由不产生任何用户方案、结果、正文或选图批准。现有 Word/LaTeX 正式汇编仍沿用原确认门禁。

## 请求示例

```json
{
  "task_id": "example-routing",
  "question_id": "q1",
  "version": 1,
  "role": "modeling",
  "stage": "planning",
  "request_id": "read-inputs-v1",
  "contract_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "query": "分析线性规划的适用条件、量纲和最小二乘推导",
  "inputs": ["problem.pdf", "data.xlsx", "notes.docx"]
}
```

示例摘要仅是格式占位；真实业务由现有 Workflow 提供实际契约摘要，不采用示例值作为批准。可选 category、algorithm_ids、math_ids 只能指向已注册类别和规范条目。CLI 是受信本地调用入口，G 阶段宿主接入还需按工作流实际任务权限调用。

## 验证与剩余范围

验证区分规则/拒绝/恢复测试、真实文档工具、真实数据库配合合成模型回执的流程回归，以及安装到源码树之外后的实际执行。测试中的合成审查和 TEST_SIMULATED_USER 仅验证门禁程序，不是实际业务独立审查或真实用户批准；三手上下文读取探针也不是真实模型三手全链路。

完整真实业务三手、实际供应商输出与独立质检、Harness 端到端继续作为 F6.6/G/H 的后续工作，不能因注册项、文件、单元测试或工具运行成功而登记整体通过。F5 暂缓项和先前用户跳过的全新 Windows 验证分别保留，不扩大本次验收。
