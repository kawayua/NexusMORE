# ModelCrew 阶段 A 开始前准备清单

本清单依据 `modelcrew-agent-plan.md` 中“阶段 A：范围与单题基线”整理。准备齐全后，再一起选题、写验收口径并搭建最小基线。

阶段 A 要回答的问题是：**给定一个公开赛题的小题，系统能否生成有依据的建模提案、求解代码和可核验结果，并完整保留运行记录？**

- [x] 你已创建远程仓库：https://gitee.com/yaukin/modelcrew-agent.git 。
- [x] 本机已检测到 Git 2.54.0、Python 3.13.5 和 Docker 命令。
- [ ] 当前工作目录尚无 `.git`；远程访问、仓库初始内容及推送权限待验证。
- [ ] Docker 服务及容器运行能力待验证；检测到命令不等于已有受控执行环境。

## 你在开始前准备的材料

### 试验题目与输入

- [ ] 选一个自己熟悉的公开数学建模赛题，并明确先做哪一个小题。若还没定，可以准备 1～2 个候选供我们一起筛选。
- [ ] 准备完整题面、该小题所需附件、官方来源链接及年份/题号。
- [ ] 简单说明附件格式、数据字段含义和单位；不清楚的地方直接标记“待确认”。
- [ ] 说明该小题是否依赖前面小题的结果；首轮优先选可独立求解、数据完整、计算量适中的小题。
- [ ] 用几句话写下你的理解：它要解决什么问题、你熟悉什么方法、什么结果看起来明显不合理。
- [ ] 确认材料可以用于本地实验；公开可访问不等于可以任意再分发，是否上传原始附件需按来源使用条件判断。

不必先准备多篇优秀论文或大量算法资料。已有参考解法可以提供，但应单独标记为人工核验参考，并记录是否提供给模型。

### 模型调用条件

- [ ] 确定首轮使用的模型供应商、模型名称、API 地址和接口类型。
- [ ] 准备可用 API Key，仅在本机配置，不写进聊天、代码或 Git 仓库。
- [ ] 给出可接受的首轮费用上限；如果暂时不清楚定价，先核对价格，再决定试跑次数和调用限制。
- [ ] 确认本机能够访问该服务；连通性在搭骨架时用最小请求验证。

首轮只接一个模型，不需要提前购买多家服务，也不需要先决定复杂的模型分级策略。

### 仓库与本机条件

- [ ] 确认 Gitee 账号能够访问和推送上述仓库；认证通过本机 Git 凭据或 SSH 管理，不在聊天中发送密码或令牌。
- [ ] 确认仓库是否已有 README、许可证或其他初始提交；关联本地目录前先读取远程状态，保留已有内容。
- [ ] 为输入附件及每次运行的代码、日志、图表留出本地存储空间。
- [ ] Python 版本按实际依赖兼容性确定；当前已安装 3.13.5，无需现在自行重装或全局安装一批依赖。
- [ ] 若希望在 A 阶段执行生成代码，准备 Docker Desktop 等可用环境，之后共同验证隔离与资源限制。

Docker 暂不可用时，仍可用人工验证过的固定代码和结果联调流程；该记录必须标注为“流程联调”，不能算作生成代码执行成功。

## 开始阶段 A 后，我们一起完成

以下是本阶段任务，不要求你提前做完。

- [ ] **冻结首轮范围**：确定唯一小题、输入文件及版本，写清本轮要回答的问题和暂不处理的内容。
- [ ] **先写人工验收清单**：列出必须输出的结果、必要图表、约束、量纲/数值检查和核验方法；没有可靠参照的内容标记为待判断，不编造标准答案。
- [ ] **建立最小仓库骨架**：关联远程仓库，建立独立 Python 环境、依赖声明、配置示例和忽略规则；README 写明项目为辅助与流程研究工具，不用于实际竞赛作品提交。
- [ ] **接通统一模型适配层**：模型名称、地址和密钥从配置读取；保存提示词版本及调用记录，日志隐藏敏感信息。
- [ ] **跑通串行流程**：题目读取 → 建模提案 → 代码生成 → 人工审阅 → 受控执行或固定结果联调 → 结果报告。未经审阅的生成代码不直接在宿主机自动执行。
- [ ] **保留每次运行证据**：分配独立 `run_id`，保存输入快照、配置、提案、代码、执行状态、日志、产物和报告；失败也保留。
- [ ] **固定口径重复运行**：记录实际次数、耗时、可获得的 token/费用和结果差异，区分理解题意、模型假设、代码实现、数据处理、结果解释及服务故障。
- [ ] **形成基线小结**：保存完整样例与失败记录，用实际问题决定 B 阶段契约需要约束什么。

首轮建议先做 1 次连通性检查和 1 次完整试跑；确认费用与链路后，再决定重复运行次数。少量试跑用于发现问题，不据此宣称整体成功率。

## 开始条件与结束条件

**可以开始 A 的最低条件**：已选定或备好候选小题，题面和必要附件可取得，模型接入方案已明确，仓库可以访问。Docker 不是整理题目和搭建骨架的前置条件，但真实执行前必须验证执行环境。

**A 阶段结束条件**：固定输入可再次发起运行，能够按 `run_id` 找到提案、代码、真实执行结果或明确标注的联调结果、日志和报告；人工验收可复核，所有尝试及失败有记录，并明确下一阶段要解决的交接问题。

A 阶段暂不建设 PostgreSQL、Qdrant、MCP 服务、七角色 Agent、完整界面和总论文。这些依照后续阶段逐步接入。
