## PDF 后端替换评估

当前 PyMuPDF 仍在依赖和实现中，尚未移除；已在两份第三方声明中明确 AGPL/商业路线未解决。使用位置包括 pdf_checks 的全页渲染、字体大小/文本越界检查，paper_layout 的实际首页与正文分页核对，paper_render 的双格式正文和页面检查，以及 paper_export 的图形边缘裁切。仅删除依赖或将 import 改名会破坏现有能力，不作为可接受替换。

候选方向为 PDFium 渲染结合 pypdf 的结构/嵌入字体检查，并通过 PDFium 文本 API 保留字体大小和字符边界检查。pypdfium2 / PDFium 原生组件许可及固定版本来源仍须先核验；已安装文件名扫描缺少许可文本仅为待补证据，不能据此断言无法授权或已获授权。后续还需核对旋转/裁切页面、中文和数学文本、全部页数、像素限制、字形/字体风险、不可提取文本及失败状态，再进行真实 PDF 全页预览与检查；不得用仅生成 PNG 的弱化方案替代现有门禁。

本轮仅落地主许可证与打包检查，未更换渲染后端、未改变数值或论文业务流程，没有生成新的论文 PDF；因此无需把旧 PDF 审阅重新登记为本次功能验证。现有 F4 冻结包/回执及 F5 首轮盘点保留。本轮构建与许可完整性证据见 release/project-license-adoption-20261114.json；F5 仍需完成依赖/工具/镜像/模型/字体与来源审查。
