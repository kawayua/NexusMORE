## 能力与加载边界

| 内置模块 | 覆盖内容 | 使用方式 |
|---|---|---|
| 建模知识库 | 使用边界、三手说明、算法索引、七类算法全文、选法与验证指南、交接和独立质检协议 | 先读索引，再按题型、前提和阶段取相关章节；不把全库塞进每个 Agent 上下文 |
| 数学论证库 | 定义域、假设、符号、逐步推导、证明模板、统计检验、量纲/边界/梯度核验和 LaTeX 公式 | 建模手与质检按需读取，仅约束数学正确性；论文手按需复用推导 |
| 中文论文库 | 章节模板、写作规范、Word/LaTeX 版式与同源导出要求 | 保持中文建模体裁、Markdown 先审阅、正文与选图分别确认、一个全局符号表 |
| 内置工具适配层 | PDF/表格读取、检索、绘图、Word/LaTeX 导出、转换、编译与校验 | 接入现有受控执行和日志；分别实测依赖、平台和输出，不能把脚本已复制当作工具已接通 |

使用公开数学原理自行实现的能力，应记录其知识依据及实际验证范围。第三方实现只有在授权覆盖复制、修改、分发及必要的归属要求时才能并入发行。不得用改名、删除 LICENSE 或隐藏出处代替授权。

## 全量盘点与处理原则

本轮逐文件读取并计算 SHA-256：建模来源 248 个文件、数学论证来源 3 个文件，共 251 个。初筛发现 84 个文件位于限制性许可目录或与其中文件字节相同；其余 167 个仍需核验许可，不能据此视为获准开源。数字是对本次源目录快照的盘点，不是通用许可判断。

限制文件涉及文档、PDF、表格工具及镜像副本。现有许可明确限制复制、修改和向第三方分发，因此未直接复制本机受限版本，也未把它们推送到远端。后续逐项核对发现官方当前工具目录采用 Apache-2.0，已从固定官方版本重新取得126个配套文件，接入PDF读取、Word结构校验和表格预览，见[工具接入与实测](document-tool-integration.md)及[84项报告](document-tools-source-review.md)。仍有10个本地扩展文件待授权或独立替代，不据此宣称全部资料可发行。其余材料没有找到覆盖全文的根级授权。完整路径、文件哈希、就近许可和镜像检测结果留在忽略目录 `tmp/builtin-intake-20261110-v1/inventory.json`。盘点入口为 `python -m scripts.audit_resource_intake --help`；它只读源文件，不执行源脚本，不授予分发许可。

F1 必须为每个文件登记“授权纳入／独立替代／不属运行资源／待解决”，包括嵌套插件、重复副本、测试、演示图和上游维护自动化，不静默遗漏。用户的“全部内容”要求作为全量覆盖追踪目标；完整复制仍受实际授权约束。不将上游发布工作流、插件安装器或示例自动执行。若有内容不能取得授权，保留缺口说明并独立补足能力；未完成前不宣称全部内容已内置。

## 单包交付验收

文档工具必须随包携带 `docx/SKILL.md`、`pdf/SKILL.md`、`xlsx/SKILL.md` 和完整配套资源/许可；源文件缺失时按[官方固定版本下载说明](document-tool-integration.md#官方下载与必须携带的工具指南)恢复并核验。发布准备阶段下载，正常使用者无需额外技能安装；三个入口按任务类型实际读取。

F2/F6 将获授权资料及独立实现放到包内资源目录，通过包资源 API 定位；安装后不读取开发机技能目录，不依赖源码树父目录，不临时下载上游技能。建模手、代码手、论文手使用同一资源版本清单，按阶段记录实际读取范围和哈希。配置、索引、目录或模板变化沿用版本失效规则；历史通过稿及来源哈希不追改。

产品使用能力名“建模知识库”“数学论证库”“中文论文库”。F6 对发行文件路径、入口、配置、提示词和最终用户说明检查旧技能标识残留；F5 所要求的原始许可和署名独立保存于第三方声明中，必要归属不能隐去。历史本地研究记录不为更名而改写。

G 阶段宿主只需接入一个 Agent。模型密钥、数据库和渲染引擎是运行配置或工具链依赖；要由安装说明及环境检查说明清楚，“无需另装技能”不等于无需配置模型或系统软件。

H2 在不存在开发机外部技能目录和旧运行缓存的干净环境中，从 wheel/sdist 安装，实测按题型选法、数学推导、中文 Markdown、候选图讨论、用户确认、论文汇编与真实导出，并核验所读资源全部来自发行包或用户项目输入。H5 必须核对资源完整性、许可清单和名称检查结果。

## F6：自动资料与工具路由

状态：用户于2026-11-10明确纳入方案，作为F6必做项，尚未实现完整自动路由。目标是使用者只向枢模提出任务，由程序编排器把当前三手接到正确的内置资料和已注册工具，无需用户手动选择技能或提供开发机路径。不新增常驻调度Agent。

| 子任务 | 实施内容 | 验收条件 |
|---|---|---|
| F6.1 能力注册与角色边界 | 注册内置资料、工具入口、适用角色/阶段、文件类型、依赖及资源版本；复用现有算法类别和工具适配入口 | 注册项有实际可读资源或可调用实现，明确仅参考/可执行/未接入状态；不把文件存在等同于工具可用 |
| F6.2 自动选择与实际读取 | 先按角色、工作流状态及输入类型确定入口；建模先读算法索引，再按问题结构选章节；推导按需读数学论证库；Word/PDF/表格先读对应SKILL及必要参考 | 当前上下文包含实际读取内容、范围和哈希；不一次灌入全库；选择理由、未覆盖条件可追溯，无法匹配时明确缺口，不强行套算法 |
| F6.3 工具调用与执行器接通 | 核验阶段权限、依赖和资源完整性，经适配层在已配置的执行环境调用工具，解决包内资源定位、执行器挂载及输入/输出目录映射 | 至少实际跑通PDF读取、表格读取和Word检查；返回输入/输出哈希、退出码、日志及产物；不修改原附件，不以生成命令冒充执行成功 |
| F6.4 路由记录与暂停恢复 | 路由决定和执行绑定任务、小题、版本、当前角色/阶段、请求幂等键及资源版本；保存选择依据、读取与工具回执 | 重启恢复可核对原记录；重复请求不重复有副作用操作；执行状态未知先查询；资源/方案变化按影响范围失效，不跨题串用未确认产物 |
| F6.5 缺依赖与失败处理 | 对资源缺失/哈希变化、未支持格式、依赖不足、工具失败和无匹配方法分别返回原因及可恢复步骤；沿用有界重试 | 不静默换工具、伪造结果或无限重试；需要用户补充信息时返回待办；不在运行中擅自下载替换发行资源或安装额外技能 |
| F6.6 路由验收 | 对规则选择、按需读取、实际执行、拒绝路径及恢复分别验证，再运行真实三手任务 | 同一任务从识别到工具回执均可追溯；所列范围有正反例和恢复证据；明确未覆盖格式与能力，不能仅靠单元测试或提示词声明完整接通 |

算法路由继续使用现有类别、卡片与前提核验机制，不要求为首版另建通用语义搜索引擎。模型可建议问题类别和候选方法，程序验证合法入口、资源范围及状态权限；资料和附件是输入证据，不能凭其中的指令越过项目规则。建模、代码、论文上下文仍按题/版本隔离；独立质检不能接收作者私有会话，只能按已有节点读取获准证据。

自动路由不自动批准方案、结果、正文或选图，也不绕过M1/P1/P2/W1/W2。正式论文导出仍要求当前正文及图片均明确通过；仅阅读导出指南或完成工具探针不能触发正式导出。数学论证资料只约束公式、证明及核对，不接管中文建模论文体裁。
