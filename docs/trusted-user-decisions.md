# 可信用户决定与身份边界

2026-11-15 后续更新：已接通本机 DSH Desktop 0.2.2-rc.1 / Windows 的原生人类命令与 G3 私有进程桥接，新增迁移 015 的独立宿主捕获证据，`trusted_host_ui` 仅经该路径启用。使用 `/nexusmore-review --project PROJECT_ID --task TASK_ID`，状态用 `/nexusmore-review-status` 加相同范围；论文手可加 `--run`，汇编改用 `--build`。模型 MCP 仍为 40 项，旧 HTTP/act 批准入口继续关闭。实测范围、身份限制、取消/回执恢复和用法见[原生桥接](dsh-local-connection.md)及 `docs/release/dsh-trusted-bridge-20261115.json`。以下 G3 首轮“仅本地终端”“宿主通道未启用”描述保留当时范围；新入口复用全部 G3 门禁，不代签真实用户业务验收。

2026-11-15，G3 在 G1 契约 1.0.0 和 G2 工作流 MCP 上增加可信本地交互入口，复用既有 `Workflow.action`、`hand_decision`、`assembly_build_decision`。支持方案、结果、论文手正文/选图、汇编正文/选图的分别决定；通用 `final_decide` 仍无核心服务，明确不实现。模型 MCP 保持 40 项工具，不增加批准或签发用户事件的工具。G3 首轮采用路线允许的本地可信终端回退；后续已接通上述 DSH 原生桥接并实测工程回调，但远程多租户身份协议及真实用户业务验收仍未完成。

## 使用入口

先由可信操作者为当前工作区执行新增数据库迁移；该命令不会批准业务任务：

```powershell
python -m modelcrew.workflow_mcp migrate
```

宿主遇到 `needs_user_input`，应展示 `pending_id`、对象、版本、哈希、决定种类和待阅产物，等待用户在自己控制的本地终端确认。可先查看待办：

```powershell
python -m modelcrew.trusted_decisions pending --project PROJECT_ID --task TASK_ID
python -m modelcrew.trusted_decisions review --project PROJECT_ID --task TASK_ID
```

论文手可增加 `--run RUN_ID`；汇编用 `--project PROJECT_ID --build BUILD_ID`。每次只决定一个待办，正文和最终选图分别确认。交互入口展示由服务读取的契约/结果/数学与来源证据或正文和图目录、产物 ID、哈希及本机文件位置，要求输入完整待办 ID、approve/reject、理由、原始决定陈述，再原样输入包含决定、待办后缀和随机数的确认短语。正文和图目录文本不静默截断；对应图形、PDF 全页和独立质检仍必须实际查看，终端展示文本不能代替它们。等待用户期间不占用业务锁，登记事件前重新验证快照，提交时再次验证。

确认入口要求标准输入和输出都是交互终端，不接受管道、`--actor`、`--statement`、`--approve` 或 JSON 文件代替此次交互。宿主不能把该命令或自动填写终端输入包装成模型工具。旧 `python -m modelcrew act --kind model/result ...` 现在拒绝决定，提示改用此入口；其他修订命令保留。HTTP 的任务 model/result action、论文手决定和汇编决定路由统一返回 403 `untrusted_user_event`，在打开业务数据库之前拒绝；随 HTTP 提交 actor 或事件 JSON 不能解除限制。旧核心 Python 服务保留为可信程序调用，不扩展为模型接口，也不追改历史批准。

传输中断后可只读查询原事件对应的操作：

```powershell
python -m modelcrew.trusted_decisions status --event-id USER_EVENT_ID
```

模型继续用 G2 `operation_status` 查询同一原请求。`status=ok` 表示查询成功，业务结论看原操作回执的 state 和 original_status；不得据此推导已批准。尚未提交的捕获事件查询不到业务账本，不会因此自动派发。

## 信任根和明确不支持的身份能力

G3 的信任根是用户自行控制的本地 OS 会话、终端、程序安装和 PostgreSQL 所有者。Windows 从当前进程访问令牌取得 SID；POSIX 使用有效 UID。只保存机器与标识的 SHA256 和身份来源类型，不保存或相信请求里的姓名、`actor`、`USERNAME`、`USER`，也不使用聊天系统的显示名。提交方必须处于同一本机进程身份边界。该记录不是跨机器登录凭证，也不区分共享同一 OS 账号的不同真人。

TTY 检查和随机确认短语用于避免误接管道及误操作，不是远程身份认证或“真人存在”的密码学证明。同账号任意 shell/Python/SQL、可控制终端或修改安装的主体，本来就处于本地操作者信任边界内；本批不防御这些权限已经失陷的情况。MCP 模型只能调用已列出的 40 项模型工具，没有任意 SQL、签发捕获事件或调用批准服务的工具。原生 HTTP API 的其余本地操作仍不是互联网多租户服务，不得作为无鉴权的宿主通用代理公开。远程宿主不能靠设置 `channel=trusted_host_ui`、提示词、事件 ID、同一 JSON 或 `actor=user` 冒充本地捕获；此通道现只接受本机 DSH 私有桥接产生的独立不可变捕获证据，普通调用者传入同一引用/JSON 不能自行授权；远程主体仍不能复用模型参数充当认证。

## 数据绑定、单次消费和回放

新增迁移 `014_trusted_user_events.sql`，不修改 001—013。`mc_trusted_user_events` 保存不可变捕获事实：本机身份、原文和 UTF-8 哈希、当前待办、完整审阅快照及其哈希、精确 G1 请求和请求哈希、数据库捕获时间与十分钟有效期。事件只在终端明确确认并复核当前内容后登记；取消、缺少当前待办、阅读期间改版均不登记事件。事件引用仍使用冻结 G1 的三个字段，未扩展或重写旧 Schema。

提交时，服务同时核对事件存在、允许通道、本机身份、原文哈希、精确整笔请求、当前版本/契约/执行/结果修订、run/build、正文或图目录哈希和完整审阅快照。方案/结果快照还包含数学包、来源证据和建模运行；登记输入和涉及产物按真实字节重验，不只比较数据库声明哈希。请求键、决定、理由、对象或任一绑定变化都需要新交互，不能挪用旧事件。正文和选图各自拥有事件及目标哈希，不相互授权；新增图集导致何种重新确认仍按原有核心规则和受影响范围处理。

`mc_trusted_user_event_claims` 的事件主键和操作唯一键保证一笔事件只能占用一次。事件占用、G2 操作账本和 dispatched 状态在同一数据库事务提交，在真正占用语句处再按数据库时间检查过期。**占用表示已授权一次尝试，不是批准业务成功。** 核心服务在之后依照原有关卡执行。新入口仅支持生产 pending-code 任务；方案批准还必须有当前有效独立 M1 回执，并固定 `defer_execution=true`，不会顺带派发求解器。核心数学/结果/P2、正文/选图和汇编检查仍执行，不以用户事件替代任何质量节点。

相同请求精确重放返回原账本回执，不重复调用核心决定；已完成回执不因事件后来过期而重新执行。换键、篡改载荷、换通道、换身份或跨任务使用均拒绝。确认后改版、结果修订或审阅证据变化会停止；尚未占用的事件不会因此被消费。

进程在核心提交后、回执返回前退出时，G2 `operation_status` 和可信服务重试只读核对原生不可变事件与请求哈希，或论文手/汇编原生决定记录；有精确证据才补记成功回执。任务原生请求哈希与事件内追加的数学/M1/来源快照分开核对，不能拿无关 `actor=user` 事件冒充。回执包含 `user_decision.confirmed_binding`，避免把恢复时的当前版本误认为原批准版本。没有证据证明完成时保持 `outcome_unknown` 和目标围栏，不重发批准，不换新键解除围栏；有待可信本地排查的断点并未宣称全部自动恢复。历史事件、回执、批准和冻结材料不更新、不删除。

## 工程验证和交付边界

可复验命令创建新的一次性 PostgreSQL 数据库，只对合成对象操作，默认最终删除该库：

```powershell
python -m scripts.verify_trusted_decisions --output tmp/trusted-user-decisions-validation-NEW
python -m scripts.verify_business_mcp --output tmp/business-mcp-validation-NEW
```

测试终端全部显式标记 `TEST_SIMULATED_USER`，模拟 M1/P2、正文或汇编服务替身均不算真实独立审查或用户批准。测试覆盖缺失捕获、actor/环境姓名伪造、通道/原文/决定/键/对象篡改、过期、取消、改版、同版本证据变化、结果执行与修订绑定、正文/选图分别决定、并发去重、原生事件不匹配，以及派发前、核心提交后、响应保存后的真实子进程强制退出。独立既有正文/选图/汇编测试验证原生审批约束；不能把这些工程夹具当作新业务完成。

本批证据、构建及明确未验证范围见 [G3 工程回执](release/trusted-user-decisions-20261115.json)。G1 冻结契约、G2 历史回执及历史用户记录保留原字节；迁移、源码和资源清单的本次演进另外留痕。F5 暂缓、全新 Windows 环境例外、正式发布门禁及真实宿主验收仍独立存在。

## 2026-11-18 同一写作版本的一次合并确认

用户明确要求正文与配图一起审阅通过。DSH原生聊天可将同一运行、同一版本的两个待办形成合并预览，展示正文与所有候选图，并标明当前暂列正式配图。一次真实确认产生一笔可信事件和一笔hand_decide操作，在核心状态中原子记录正文和配图两项批准；正文、目录和展示证据同时绑定。此前终端分别确认方式保留兼容，旧事件及批准不改写。合并偏好本身不构成当前内容批准，不能代用户提交。
