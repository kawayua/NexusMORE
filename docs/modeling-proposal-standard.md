# 建模方案审阅标准与执行边界

2026-11-17 用户确认：面向用户的建模方案必须讲清楚模型，不能交付内部契约摘要或用 M1 PASS 替代内容质量。新建模运行冻结 collaboration 1.4.0 及建模方案协议1.0.0，旧冻结运行、来源、批准和回执保留原字节。

## 阶段要求

建模方案不是完整论文。必须提供问题分析与建模思路、逐条假设及依据/影响、一张统一符号表、方程与约束推导、离散或算法求解流程、检验公式/比较范围/阈值依据、局限与来源。当前没有执行结果时只写验证计划，不要求结果图或数值结论；正式论文继续走既有论文手与正文/选图确认流程。

适用的数值方案应说明控制体或节点、非均匀权重、轴心/边界/角点、面系数和守恒通量；非线性残差、迭代方式、停止条件、上限与失败处理。稳定性应核对实际控制方程的扩散率、单位与参数；物理量同单位不等于同基准。加密验收门槛与观测收敛阶分开，不把1.5称为二阶证明。非数值题逐项声明不适用并给出理由，不强塞网格或 PDE。

## 程序实际执行

新建模请求的 Proposal 必须提供结构化 review_document。程序检查必需字段、内容最小长度、中文说明、推导中的LaTeX数学表达、唯一符号、已提供来源ID、数值条目的适用性说明，并拒绝正文混入 baseline、edits=[]、chk_、内部公式ID和审核状态等日志。程序据该对象渲染用户看到的 proposal.md，追溯元数据仍独立保留。

结构检查在任何契约/数学包修订写入之前完成；失败沿用最多一次自动纠正预算。结构通过只表示可审阅，不表示数学正确。规范随运行冻结，不从用户正文中执行指令。正式用户稿的字节摘要与快照中正文绑定，M1后若稿件改变，新的模型准入拒绝。

独立 M1 保持既有六项门禁，但必须额外逐项核对13个标准：问题理由、假设依据、符号单位、物理量基准、推导、初边值、离散、非线性、稳定性、检验定义、收敛、局限来源、可读性。每项引用 proposal 的对应 review_document 子段落；数学与事实还要引用契约/数学包/原始证据。程序验证覆盖完整且唯一、引用实际可解析；缺项/引用不充分降为 BLOCKED，细项 FAIL 降为 FAIL，不能被冗余总体PASS覆盖。真实审查内容保存在 proposal-audit.json，原始模型响应与最终回执同时保留。

程序不自动证明方程、物理假设或收敛性；逐项语义判断仍来自未参与编写的独立审查上下文。完整覆盖也不能宣称零漏审。M1后的模型确认、后续真实计算、P1/P2及结果确认继续分别执行。

## 历史与部署

新规范只自动作用于新冻结建模运行。旧方案/旧M1不会被批量改写或静默重签。需要纠正旧方案时在同一未批准任务上启动新建模运行，生成新目录和回执，依影响范围走版本化修订。新规范本身不改阈值、既有模型或用户决定。已运行 MCP 后端需重新连接加载新源码；独立本机工程测试不代表宿主已重连。


## 完整提案文件送审入口（2026-11-17）

`modeling_start.arguments.proposal_files` 可指定 `{path, sha256}`。文件必须在后端工作区内、不是链接、有效 UTF-8 JSON、大小不超过 2 MiB，并绑定当前任务、版本、契约及数学包哈希。顶层字段为 `binding`、`plan`、`proposal`、`authorship`；其中 `plan` 遵循现有 Plan，`proposal` 遵循现有 Proposal 且 `edits=[]`，`authorship` 为 `{kind: "prepared_file", statement: "实际作者与来源说明"}`。来源卡片仍从本机内置库按计划读取，不能借文件伪造参考资料或审查结论。

入口保留原始文件字节、文件 SHA 与作者来源记录。正式正文经原结构模型解析和统一 Markdown 渲染；只允许原有模式的空白规范化与缺省字段展开，不调用供应商模型重写正文。作者记录明确 `provider_call=false`，不能冒充远程作者调用。之后仍创建当前任务的新快照，调用独立上下文 M1，并按原六项语义检查和十三项证据审计准入；失败不会自动生成另一份正文，也不自动批准模型或启动计算。正文改动需新文件与新快照；契约/数学语义改动应先版本化修订。已经运行的 MCP 进程需重连后才能发现新参数；工程本地调用同一 BusinessAdapter 无需冒充用户确认。
