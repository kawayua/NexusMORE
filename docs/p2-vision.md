# P2 全页图像输入与独立视觉审查

2026-11-18。P2沿用同一个独立质量上下文，不新增常驻业务Agent、不读取作者聊天、不授予用户批准。下层JsonModel原已支持image_inputs；本次将coding_review的全部真实PDF页预览接入provider，并新增完整覆盖/发送证据校验。

容器产物和全量复跑保持不变。宿主对候选目录的所有PDF做完整页数检查、渲染与校验；p2_vision.prepare将每一个物理页的PNG字节、源PDF/预览哈希、尺寸、页号和标签组成不可变manifest，加入同一P2快照。每张PNG也单独进入快照并封存。新协议最多100页；超限明确拒绝，不抽页、不截断。数值工程零图特例仍按其已确认范围处理。

provider的请求摘要覆盖实际图像发送清单；JsonModel发送原生image_url/data:image/png;base64，持久记录图像数量、每图SHA256/字节数、总字节、配置及返回模型、请求记录哈希、响应哈希和token usage。HTTP错误/传输未知不自动换模型或降为纯文本。未送达恢复核验多模态原请求中的实际base64图像哈希，不把有回应的模型格式错误当未送达。

模型逐页只返回image_id、status和具体可见观察。模型不抄写64位哈希；程序从冻结且实际发送的manifest把ID绑定回SHA256。严查页数/ID完整且唯一、实际发送图像集合与冻结集合一致；任何图片FAIL/BLOCKED均不能有figure_meaning PASS。13页的独立视觉回执与同一次P2的reviewer身份、ticket、snapshot和正式receipt绑定，并封存原始请求/响应/元数据。候选结果登记前verify_result再次核验该完整关联；作者自检和旧PENDING字段不能冒充独立审图，也不能被当成这次真实图像审核不存在的循环理由。

可选配置`MODELCREW_VISION_MODEL`或用户settings的model.vision_model只用于带图的P2，沿用当前模型服务地址和密钥；未设置时使用当前主模型。该字段不配置另一供应商的地址/密钥，也不影响M1、P1或W2。更换模型/服务后必须实测视觉能力，不因名字、image_tokens字段存在或API兼容就宣称支持。没有自动模型回退。

本次已对配置的deepseek-v4.1-flash-1017实际发送一张随机文本/随机色块图，预期值只在图片像素和本地验证文件中，回答准确且image_tokens=191。之后正式P2实际发送13页，解码发送请求逐张验证SHA256，发送811485字节、image_tokens=4558；13页逐页报告与全部P2检查均PASS。这只证明本次已配置服务/模型、实际请求及图件，不概括其他模型/供应商的视觉能力。

新能力就绪后可由可信维护入口resume_existing_visual_failure复用同一运行已成功全量/复跑的原文件：只允许上一P2仅figure_meaning失败、尚未领取新源码/执行的全量返工阶段，重验原P1、P2、源码、46文件哈希及复跑一致。旧失败、作者attempt/retries和修复/复核额度均保留；不重算、不回写历史。该维护入口不作为模型批准或结果批准工具。旧已接受的纯文本P2不追改，新P2必须产生自己的实际图像发送和审查证据。
