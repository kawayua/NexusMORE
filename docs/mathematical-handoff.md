# B+ 数学交接契约与确认机制

更新：2026-11-06。B+在既有工作流上增量实现数学交接，保留旧业务契约字节含义与哈希；不重写历史验收。[工程验收](../stage-b-plus/acceptance-report.md)与[可读提案](../stage-b-plus/proposals/bench-dragon.md)可直接检查。

## 内部结构

| 工件 | 内部内容 | 作用 |
|---|---|---|
| MethodSelection 1.0.0 | 问题指纹、模型与求解器、候选稳定ID、唯一选择、前提、数据、风险、来源、验证与替代路径 | 解释为什么选这个方法和为什么没选其他方法 |
| MathematicalDossier 1.0.0 | 问题范围/输入/待求结论、符号及单位/域/形状/作用域、假设及来源影响、公式、推导/命题条件步骤与缺口、未证事项 | 保留模型的数学含义，不将数值观察改成证明 |
| MathematicalPackage 1.0.0 | 上述两项、公式到契约字段的引用、带阈值/单位的验证计划、图示规格和数据来源、资料哈希、封闭排版选项 | 作为可验证、可版本化的交接整体 |
| 数据库绑定记录 | task_id、业务version、数学展示revision、契约摘要、包摘要、语义摘要、可读提案摘要、TeX、作者/原因/变更类型 | 确认具体内容，保留不可覆盖历史 |
| 确认快照 | 用户动作中的任务/业务版本、数学revision及上述摘要；结果确认另加结果revision、execution_id、结果审核摘要 | 追溯“这个人确认的究竟是哪一份数学与结果” |

正式Schema位于contracts/，数学包与原Model Contract分别存储。每个公式必须有且仅有一条contract_links记录：明确引用现有参数/变量/假设/约束/检查项，或说明它仅用于解释/推导。引用合法不等于已自动证明公式与代码等价，仍需用户审阅。板凳龙样例引用head_arc、chord、velocity_relation；LP样例绑定独立资源约束，未借用板凳龙契约。

计算事实继续保存在既有mc_results、mc_executions中；不为补入结果而修改已冻结的建模数学包。结果确认快照将这些记录与同一数学语义绑定，后续Writer可联合读取。历史v2数值及图示数据若被引用，标为历史证据，不冒充新业务版本运行或新批准。A+原result_binding中的旧批准未复制成B+批准。

## 摘要与同源展示

package_sha256覆盖完整JSON；semantic_sha256覆盖任务ID、业务版本、原契约摘要和除presentation外的完整数学内容。数据库中即使JSONB重排对象键，也使用相同排序生成Markdown与摘要。每次展示重算摘要并比对冻结的Markdown/TeX，发现不一致即失败。

Markdown与TeX从同一结构化包生成，不接受独立手写展示覆盖字段。先定义符号，随后展示假设、稳定公式标识及有条件的推导；Markdown附完整语义快照，避免正文省略来源/条件。TeX记录命题状态和缺口，真实编译及最终版面检查归C+。同源展示保证内容可追溯，不能证明任意LaTeX成立。

## 变更与失效

| 操作 | 新业务版本 | 确认与计算处理 |
|---|---|---|
| 改假设、变量域、公式、方法、容差、验证或图示数据/聚合含义 | 是 | 模型/结果批准清空，执行指针与结果revision重置；旧记录保留；重新审阅、确认并进入执行 |
| 仅改presentation.equation_spacing | 否，数学revision递增 | 语义摘要不变；原计算和双确认保留，标记需重新导出 |
| 修改任意LaTeX或符号名称/单位 | 保守按数学变化 | 当前不实现自动等价证明，不能自行归为排版；只调整明确排版开关可保留确认 |
| 只改结果解释 | 否，结果revision递增 | 沿用原解释审核，保留执行、结果批准失效；新结果确认绑定当前数学与新revision |
| 回退数学/契约版本 | 是 | 拷贝历史来源作为新版本，不恢复旧批准；重新检查输入文件，保留restored_from_version |
| 已批准历史任务首次加入数学包 | 是 | 不允许原版本补挂数学包并追认旧批准；必须创建新业务版本 |

B+当前采用保守策略：所有数学变化均重走求解关卡，尚不自动判定“修改证明但无需重算”等更细的影响范围。模型变更时已有数学包不可省略；恢复时带回原包。跨表示符号等价映射自动证明、手写TeX差异归一化留待后续，不虚构已完成能力。

## 持久化、接口与恢复

迁移007新增mc_math_packages，不修改旧契约Schema。数据库触发器拒绝UPDATE/DELETE；任务锁、业务事务、幂等请求表继续复用。首次挂载/排版发布有独立request_id；数学新版本与新包在同一业务事务提交，校验失败整体回滚。提交后checkpoint故障可由新进程resume恢复，重复操作不新增版本或重复执行。

HTTP沿用可信本机API：

- GET /tasks/{task}/proposal 增加mathematics及可读Markdown。
- GET/POST /tasks/{task}/versions/{version}/mathematics 查看数学包，或首次挂载/排版发布。
- POST /projects/{project}/tasks 支持可选math_package。
- POST /tasks/{task}/actions 新增revise_mathematics；revise_model可携带新math_package。
- model/result批准在已有数学包时必须传math_semantic_sha256和明确审阅reason；结果还需准确result_revision。
- GET /tasks/{task}/versions/{version} 增加当前数学快照、数学修订历史及相对上一业务版本的数学差异；即使契约字节不变也能看到数学修改。

执行前和流程完成前复核持久化数学确认绑定，真实求解结果登记也检查模型数学绑定。旧任务无数学包时保留原流程，无须改变已确认的旧Schema或补造新确认。现有actor是审计标签，不是认证；接口没有新增公开网络部署或代替用户批准的机制。

## 数学审核边界

自动检查覆盖结构、稳定ID、引用、声明的单位/维度和显式前提、已证明却留缺口等冲突。结构合法的“1=2”仍可能通过，专项反例明确演示此限制；用户确认需提交具体数学摘要与审阅理由，不能以结构通过、求解成功或编译成功替代数学审阅。没有调用真实模型生成B+材料，也没有第二位独立数学评审。
