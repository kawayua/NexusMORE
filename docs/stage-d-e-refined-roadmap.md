## 三主 Agent 内部职责与独立质检交接物

Planner/Researcher/Modeler 属于建模手，Coder 属于代码手，Writer 属于论文手；Validator/Reviewer 是临时质检职责，以下并非七个独立 Agent。每项职责只能提出其范围内的工件；编排层负责持久化与状态推进，用户拥有方案和结果最终确认权。以下新增工件名是待实现的逻辑契约，不代表已经存在的文件/API。

| 角色 | 必须接收 | 必须交付 | 责任边界 |
|---|---|---|---|
| Planner | 原题、附件清单、用户目标 | 小题任务图、数据依赖、每题结论类型和验收项 | 不预先指定模型；依赖边指向确切上游结果版本 |
| Researcher | 小题目标、数据特征、候选方法需求 | 带来源位置的证据包、算法卡片命中、适用条件及冲突 | 区分原始来源、同题参考、算法说明、外部代码；不把参考数值当本次结果 |
| Modeler | 题目事实、证据、用户指导 | 版本化 Model Contract、符号/单位表、推导依据、验证方案、方法取舍 | 形式化目标与约束，说明算法如何实现模型；不得私改数据或替用户确认 |
| Validator | 契约草稿及原始证据 | M1 报告、风险、缺项、可执行检查清单和修正建议 | 未参与被审契约写作；检查数学与可实现性，不只查 JSON 字段 |
| Coder | 已通过 M1 且获用户确认的契约、冻结输入与依赖 | 实现、最小运行入口、全量实验计划、结果与图表、复现信息 | 不自行变更模型、容差或评价指标；发现合同错误退回 Modeler |
| Reviewer | 契约、代码、真实回执、结果与图表 | P1/P2 报告、逐项证据、失败分类和返工目标 | 与生成代码的调用上下文隔离；不得修改权威代码后再自称独立审查 |
| Writer | 已获用户结果确认且通过 P2 的证据快照 | W1 证据大纲、小题结构化章节、引用与图表绑定 | 不能重新求解、补造结论或覆盖审核；章节先结构化，排版后置 |

Validator 承担 M1，Reviewer 承担 P1/P2，并在未参与写作的上下文审查 W1/W2；质检按节点调用且与作者隔离，不新增常驻业务 Agent。同一模型供应商的独立调用只表示上下文/作者职责隔离，不宣称统计独立或数学正确性保证。机械检查先用代码完成，语义审查再使用模型；模型审查不得替代沙箱执行或用户确认。

## 算法资料如何进入系统（D1）

七类索引保留：优化、预测、评价、图论、统计处理、仿真/微分方程、机器学习。它们是导航类别，允许一张卡片多个标签，避免将“回归预测”和“机器学习”视为互斥模型。

A+ 先查相关原文、C+ 建最小检索资料集，再在 D1 整合约 10—20 张与现有题目和首轮回归直接相关的卡片，不以数量作为阶段门槛；优先几何约束与求根、微分方程/积分、线性/非线性优化、误差和灵敏度分析。七类目录可先齐全，未建设的类别显式返回未覆盖。F 阶段按留出题需求扩展，不在 D 前建设原计划的 200—300 张卡片。

每张卡片至少包括：`card_id`、版本、问题标签、适用与禁用条件、假设、变量与公式、所需字段/单位、数据规模与复杂度、算法步骤、停止条件、API/依赖版本、失败状态、最小示例、验证方法、来源路径/章节/URL 与内容哈希、核验状态。文献链接尚未核验时标记候选；外部代码未运行时标记未验证，不能编造 PASS。

卡片进入现有 paper-search 语料链路，以来源类别、题型和核验状态过滤。返回命中时保留原文位置和引用标识；Modeler 必须记录采纳/拒绝及本题适配，Coder 仍只执行用户确认的契约。示例代码属于不可信输入，移植后仍走既有审阅与 Docker 执行链。

按卡片类型设置验证：优化检查可行性、残差及求解器状态，启发式方法不声称全局最优；预测按时间/分组拆分并防止预处理泄漏；评价检查正负向、常数列、权重与排名稳定性；图论检查负权/连通性等前提；统计检查独立性、配对、效应量与区间；仿真检查种子、重复次数、离散误差和收敛；学习方法检查训练/测试隔离与指标适用性。不存在适用卡片时允许基于原始文献提出新方法，不强迫套用库中算法。

## 数学能力如何进入契约（D2）

复用现有 `model-contract-1.1.0.schema.json`。先定义扩展草案与兼容映射，再决定是否发布下一版 Schema；不得为了新字段重写既有已确认契约和哈希。

- `formalize`：明确状态/决策变量、取值域、输入单位、目标或待计算量、初始/边界条件与可行性。仿真题不强行塞入优化目标。
- `derive`：对关键控制方程与约束给出可核对中间步骤、所用假设和来源；外部推导与本题新增推导分开标注。
- `notation`：在建模时建立局部符号表，记录符号标识、含义、单位、维度与作用域；E 阶段才解决跨小题冲突。
- `verify`：检查量纲、定义域、极端/退化情形、约束一致性；涉及梯度时可用适用的数值差分核查。数值核查不称为形式证明。
- `stats`：仅在本题需要统计推断时启动，先判断样本独立、配对、分组与重复测量，再选择检验、区间、效应量及必要的多重比较控制。样本不足时报告限制，不强求显著性。
- `prove`：仅在使用的性质需要论证时启动，记录前提、命题、引理来源和证明缺口；不能凭模板声称已证明收敛或最优性。

每题先考虑一个主模型及有证据价值的对照，通常控制在两个模型族内；这是复杂度预算建议，不是新的硬性模型数量限制。同一物理机制的精度改进、误差分析、灵敏度实验不机械算作新模型。

## 运行内检查点与回退

| 检查点 | 时机 | 核心检查 | 不通过时 |
|---|---|---|---|
| M1 | 方案提交给用户确认前 | 子题覆盖、公式/符号/单位、假设与引用、可实现性及验证方案 | 回 Modeler，修正后复验 |

| P2 | 全量计算与必要图表冻结后，结果提交用户前 | 契约实现、结果合理性、复现、图表与代码一致、每题证据覆盖 | 按模型/实现/解释缺陷定向返工 |
| W1 | 用户结果确认后，长篇写作前 | 每个主张的精确证据位置、引用、公式和章节落点 | 文字组织问题回 Writer；计算/模型缺证回对应角色 |
| W2 | 汇编、确定性检查与真实渲染后 | 全文关键主张、符号、引用、数值、排版及快照一致 | 回对应责任角色并重跑受影响检查 |

记录包含检查点、作者/审查调用标识、任务/契约/结果版本、输入和产物哈希、PASS/FAIL/BLOCKED、证据路径、问题严重度和返工目标。只有覆盖的检查项可判 PASS，依赖缺失记 BLOCKED，禁止用空报告放行。现有解释审核的 `unknown` 及有理由的用户人工审阅规则继续保留；不将历史记录伪装成已通过新增检查点，新流程接入时显式区分旧版适用范围。

检查点不替代方案/结果两个用户确认。确认前和恢复时重新校验绑定：模型/数据/代码/参数变更使相关下游审查失效；只改解释保留 execution，新增结果 revision，重做 P2 的解释项和结果确认，再重做相关 W1/W2。由依赖图确定失效范围，不整条链无条件重跑。

沿用求解代码最多 3 次重试、审核触发的模型回退最多 1 次，分别记录并在耗尽时转人工；用户主动发起的新版本不伪装成自动重试。基础设施失败只走 C 的恢复/查询路径，不能扣为 Coder 模型失败，更不能对未知执行盲目重发。

## 论文生成的具体调整

D 的 Writer 先交结构化章节：问题、假设、变量/公式、方法、结果、检验、局限与引用；E 负责全局排版。内部保存 `claim_id → 契约版本 + execution_id + result_revision + artifact hash + 字段/行列/选择器 + 单位/容差 + 引用位置`。可继承现有 interpretation claims 的数值取证能力，但不能声称现有标量比较已支持任意数学或自由文本审查。

图表按“数据事实—过程诊断—最终结果”检查证据用途：没有可观测迭代过程时使用真实残差/收敛或误差诊断，不伪造过程图。每题在契约中约定必要图表/表格和适用理由；同图的 PNG/SVG 不重复计数。沿用当前中文论文政策：三类候选各至少3张、总计至少9张，正式入文至少8幅；用户或官方依据覆盖需记录，不用重复内容凑数，不新增固定字数。

保留 LaTeX/PDF 的已有技术方向，E0 提前确认引擎、字体、参考文献后端、模板与渲染链。首次完整通过 W2 的参考稿保存不可变版本，后续优化新建构建。构建清单绑定模板、结构化正文、代码结果、图片、引用、工具版本、日志及 PDF 哈希；未解析引用、缺图或实际渲染问题不得标成通过。Word 作为后续可选出口，确有需求再增加 OMML、转换与跨格式一致性验收。

论文仅展示建模、求解、证据与结论；审查回执、内部检查点、哈希、成本和状态日志放在系统审计界面。研究稿使用明确标识的模板基线；若未来增加特定赛事版式，再核验目标届次官方规则，不能把参考 Skill 所述页数称为已核验的官方要求。

## F 阶段增加的评测项

保留有/无契约主对照与现有评分口径。在预算允许时，再比较按需算法卡片与不使用卡片、分段检查与只做末尾检查；不要同时改变模型、语料、重试预算和人工投入。自动检查点用于路由，统一评分人或独立评分流程用于评测，避免 Reviewer 自评成为唯一分数。

新增数学缺陷检出率及误报、P1 阻断后避免的无效全量计算、论断证据覆盖与错误绑定率、复现成功率、版本变化后的失效正确性，以及角色调用成本。没有标注缺陷集时不报告数学检出率；运行成功不等于模型正确，证据覆盖率也不等于结论真实性。开发可用带出处同题参考，严格留出评测单独冻结来源与暴露条件，不恢复已取消的 D 前空白上下文门槛。
