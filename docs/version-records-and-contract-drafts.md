# 版本档案与契约草稿设计

记录日期：2026-11-05。来源：用户要求每个版本记录Agent方案、代码、实验结果、用户反馈、下一步与相对上一版的改动，并支持回退；系统根据题面和附件起草契约，用户审阅关键假设及关注的约束。

本文是补充设计与验收要求，不表示以下功能已经实现。现有已确认的dragon-q1 v1/v2契约、哈希、结果与确认记录保持原样。

## 每版档案

| 内容 | 需要保存的信息 |
|---|---|
| 身份与来源 | task_id、version、parent_version、生成时间、模型供应商与模型名、输入快照与契约哈希；回退另记restored_from_version |
| Agent方案说明 | 可供用户审阅的方法概述、公式与依据、假设、备选方法、风险；保存实际输出的说明，不要求或伪造模型内部思考过程 |
| 契约 | 完整契约快照、结构检查、数学检查、待用户判定项及方案确认记录 |
| 代码与运行 | 代码文件与字节哈希、依赖/执行环境、每次尝试及失败记录、日志、运行状态、资源与耗时、关联execution_id；模型或方法不变的实现修复可有多次尝试 |
| 实验结果 | 数据、图表、指标、独立审核与证据、result revision、结果确认；区分fixture、真实执行、未运行，不因存在文件而宣称成功 |
| 用户反馈 | 原文、时间、作者标签、针对的版本/结果/运行、采纳情况及依据；反馈追加记录，不覆盖旧意见 |
| 版本改动 | 与父版本的结构差异，以及对方法、参数、输入、代码和结果影响的文字说明；区分已完成和计划改动 |
| 下一步 | 建议动作、依据、前置条件、执行状态与完成事件；建议与用户授权分开，不能据此自动跨过确认关卡 |

各项应有明确的未生成、待执行、失败或已有证据状态。版本档案通过不可变记录与关联产物组成；后续代码、实验、反馈和下一步事件追加到相应版本，不能为补充档案改写已确认契约。涉及未纳入契约的解释更新沿用结果revision。

## 回退语义

查看旧版无需改动当前任务。恢复旧方案时，以旧契约为基础创建新的业务版本：parent_version指当前版本，restored_from_version指被恢复版本；重新进入方案确认，当前下游引用失效，全部旧记录保留。

恢复时重新检查输入文件哈希、代码和结果是否仍可获取、依赖与复用条件。历史确认作为历史证据保留，不自动变成新版本确认。不默认把旧结果登记成新运行；如后续支持复用，必须明确记录原execution_id、来源版本、等价性检查与用户确认。

## 自动生成契约草稿

系统先识别题面与附件角色（说明文档、原始数据、输出模板、参考资料），提取可验证的文件/工作表/表头/类型/形状信息，并从题面提取参数、单位、约束及交付要求，再生成草稿和关键审阅清单。

事实应记录页码、工作表或单元格等来源定位。单位、缺失值策略或业务语义无法从来源确定时，明确unknown并提出待确认项，不擅自填成事实。用户补充或修改后生成新草稿；只有显式确认后才可求解。

同题同输入的方法改版继承已有输入结构并展示差异，用户无需每版重新填表。新文件、表头、形状、单位或缺失策略变化需重新验证和展示影响。契约格式升级应兼容旧schema，不能静默重写历史v1/v2。

## 输入数据内部结构的含义

文件路径/哈希回答“是哪一个文件”；内部结构回答“如何读取并解释里面的数据”。表格数据可约定工作表、表头位置、列名、列类型、单位、行数或形状、必填项、缺失值处理、唯一性、排序和取值限制。数组可约定轴含义、维数、形状和单位；参数对象可约定键、数值类型、单位、来源及范围。

本题没有待拟合的观测数据表。A题.pdf提供题意与参数，不应虚构成数据表；螺距0.55 m、龙头速度1 m/s等作为参数输入，需要明确数值类型、单位、来源与约束；result1.xlsx是输出模板，其工作表、时间表头、节点标签、布局与精度应作为模板结构/输出要求验证，不能当作已有观测值。

## 用户确认的数据类型基础结构规则

用户已同意：按数据类型预先定义可复用的基础结构，系统根据题面与附件生成本题契约草稿；与题意有出入、信息冲突或语义不明确时，再提交用户确认。无需用户逐个字段、逐个版本重新定义。

基础结构模板只预设需要描述的项目和结构校验规则，不擅自预设本题的单位、坐标系、缺失值含义等业务事实。初始覆盖如下，后续按实际题目扩展：

| 类型 | 基础描述项目 |
|---|---|
| 表格（CSV、Excel） | 编码/分隔符或工作表、表头位置、列名、类型、单位、缺失策略、主键与取值约束 |
| 时间序列 | 表格结构及时间字段、时间格式/时区、采样间隔、排序、重复时间与间断处理 |
| 数值数组/矩阵 | 存储格式、数值类型、维数、形状、各轴含义、单位及非有限值处理 |
| JSON/嵌套对象 | 必需字段、类型、层级、数组元素结构、允许的额外字段与空值 |
| 图像 | 格式、尺寸、通道、像素类型；用于物理测量时另需标定比例、方向及来源 |
| 地理空间数据 | 格式、几何类型、坐标字段、坐标参考系、轴顺序与单位 |
| 参数集合 | 参数名、类型、数值、单位、来源、给定/派生/假设及约束 |
| 说明文档/输出模板 | 文档角色、来源定位；输出模板另记工作表/表头/标签/布局/精度，不按原始观测数据处理 |

同一文件可组合多个结构，例如Excel中的时间序列，文件格式与业务结构分别描述。未支持的数据类型标记为待定义，不强行套用已有模板。

草稿需区分题面明确要求、附件实际观测、模板结构规则、系统建议与用户确认内容。发生冲突时展示具体位置、影响和建议；未解决的关键语义不得作为已确认事实传给求解器。即使无冲突，仍保留整份建模方案的显式用户确认关卡；此规则减少重复逐字段确认，不取消方案确认。

模板自身记录标识和版本；本题契约保存展开后的结构及所用模板版本。模板更新不静默修改历史契约，方法改版且输入未变时继承原结构，仅展示实际变化。

本节为已确认的设计规则，尚不代表上述解析器、模板库或自动确认提示均已实现。
