## 研究集准入与暴露登记

后续每道题在首次模型调用前，记录完整题目族 ID、原始来源/年份/题号、全部小题和附件清单、每个文件哈希、合法使用与再分发范围、题型/规模/强制输出、外部评分依据、开发或留出分层、登记时间、保管人及暴露审计。局部小题必须标注覆盖，不能按完整赛题计数。同一原题、翻译、改写、参数变体和共享关键附件按同一题目族分组，禁止跨开发/留出划分。确需跨题继承的研究题以完整依赖链为一个分组。

项目侧暴露区分已读题、已读解答/论文、已检索相关资料、曾调试或调参、未发现暴露、未知；记录接触者、时间、宿主历史/检索索引/文件范围及证据。未知不能当作未暴露；模型预训练污染通常不可完全核实，须单列未知，不声称绝对无泄漏。历史开发记录已有明确暴露，永久排除该版留出。留出解答、判分参考和标签由未参与该题开发的保管人隔离；评测模型/作者不读取，评测所需公开背景与检索策略则对各组一致开放并留痕。

本轮不提前查看候选留出题正文。建议首轮至少覆盖优化、动力学/几何、统计/预测三类完整研究题，各选择一个独立题目族，开发题另选；具体数量、领域、重复次数和成本上限在具备合法数据后由用户确认。此为项目自定设计建议，既非赛题要求，也非既有批准。若资源只够更小规模，预先标为试点评测并披露，不支持总体泛化结论。

## 环境与运行冻结

| 层次 | 计划范围 | 本批证据 |
|---|---|---|
| 本地数据包检查 | Python 标准库，重算两份确定参考值与核对哈希 | 由 `scripts.check_evaluation_data` 执行；不连服务 |
| H2 首发环境 | 已选 Windows x86_64 / CPython 3.13，Docker Desktop WSL2 Linux amd64，真实 DSH | 待冻结发行候选并在干净环境新运行；开发机新 venv 不等于干净机器 |
| 其他宿主或系统 | Codex、Claude Code、Linux/macOS等 | 计划/未验证，不能借用 DSH 结论 |

H2 每个环境单独记录 OS/架构、Python/Node/宿主及引擎版本、发行包与依赖锁/镜像 digest、包内资源清单哈希、字体和渲染工具、安装日志、配置脱敏快照、服务身份与初始状态。固定已支持 Tectonic 0.17.0 / Pandoc 3.6.4 基线；其他引擎和任意 TeX→Word不扩入。禁止依赖开发机外部技能目录、私有缓存、历史工件或预填成品。使用独立工作区和数据库，原用户业务库只读保护；缺先决条件记录 blocked，不能冒充模型失败或通过。

真实宿主必须从自然语言任务调用共享业务入口，记录实际资料读取、受控工具路由、用户确认、M1/P1/P2/W1/W2、跨题继承与正式导出。正文/配图按当前同一版本合并确认规则，仍保留两个原子范围；旧记录不补签。所有候选/正式 PDF 全页核对、预览、检查和哈希分别留证，实际读图、独立审查和用户确认各自执行。小样例不交付论文，研究题不因小样例通过而降低这些要求。

## 评测单元、分母与公平对照

H3 核心为同题配对的“有结构化契约 / 无结构化契约”对照；不预设胜负，不复用路线里的预期效果充作实测。无契约组只在隔离评测路径取消交给代码手的结构化模型契约，保留等量自然语言问题信息、数学正确性/安全检查和真实用户确认；不得修改生产审批机制。对照执行路径尚未实现，先验证信息等价、记录差异，再开始正式计分。独立质检、用户指导、算法卡片、分段检查消融按预算另立预注册组；七Agent实验为可选，不是本轮前置。

评测单元为题目族 × 配置组 × 重复编号。建议每组每题2次独立新运行，配对随机顺序；若供应商无确定种子支持，记录不支持，不伪造确定性。固定模型提供方/端点类型/精确模型标识、参数、提示词模板及哈希、可见输入/检索资料、工具集、每次作者重试/工具预算、总 token/费用/时限、人工可给信息及轮次；具体金额与 token 数尚未确定，未冻结预算时不得开始付费正式评测。同 attempt 复核最多一次、跨 attempt 独立记账，作者重试预算不随复核扩大。用户指导不等价时分层报告，不能暗中给某组更多解答。

首次模型/业务执行前冻结全部计划单元。固定样例/参考解答运行、模拟模型、工程探针和 G 历史回放永不进入真实研究求解率分母。主分母为全部预注册计划单元；分别报告 started / not_started / blocked / cancelled / completed，不能删除失败、超时、无效输出或取消来提高比例。另报告“已启动”为分母的条件率并明确口径。分小题与完整题分开；未完成任何强制小题不能记完整题成功。留出与开发分开报告，跨组重复按题目族聚类，不能把同题重跑当成独立新题。

| 指标 | 定义与报告方式 |
|---|---|
| 执行状态 | 首次执行成功、预算内重试后成功、失败/阻断分列；安装检查与真实求解分列 |
| 业务完成率 | 完成全部要求和人工关卡的单元 / 预注册计划单元；完整题和小题分列 |
| 数学/数值有效率 | 经独立外部标准核对的有效结果 / 计划单元；未评分、超时、缺证据分别计数 |
| 契约满足率 | 满足项 / 适用项，披露不适用和缺证据；无契约组也按相同外部要求核对，内部 Reviewer 不作唯一效果证明 |
| 缺陷发现 | 仅在独立标注缺陷集上报告检出率/误报；无标注集只报发现清单 |
| 人工成本 | 用户指导/确认/干预次数与时间，自动恢复和人工恢复分别记录 |
| 模型与运行成本 | 每次调用输入/输出/缓存 token、重试和质检费用，端到端耗时及等待人工/供应商/执行器的分项 |

成本缺失记 unknown，不能写0；记录定价来源和适用日期/币种、请求ID脱敏值、原始 usage及计费口径。失败和恢复调用同样累计到原单元；按单元和配置组同时报告计划/成功/失败总成本与分布。不在本批查询价格或调用付费服务。

## 外部评分、误差与结果呈现

采用两名未参与该题产物编写的评分者独立盲评，隐藏配置组与作者身份、随机展示顺序；如题型/材料导致可推断组别，披露盲法局限。五维各0/1/2：问题与约束覆盖（缺关键输出/部分覆盖/全覆盖）；模型假设及推导（实质错误/欠论证/条件与推导一致）；求解可复现（不可复跑/证据不完整/输入与运行可核验）；结果及检验（无有效检验/部分验证/外部标准与敏感性等适用检验充分）；中文表达与图表证据（关键缺失或误导/基本可读有缺口/单位符号引用完整且图支持结论）。总分0—10，先保留两份原分，再报告均值、维度差异与分歧处理；总分高不能覆盖物理/守恒/强制输出错误。内部 P2/W2 是过程门槛，不作为唯一外部评分者。

数值误差分别标明题目强制精度和项目自定阈值，记录实际误差、单位、时空位置、对结论影响及改善成本。本批两道整数小样例使用精确参考值，无浮点容差；真实研究题阈值在看结果前按题目冻结。用户接受的自定偏差单列 `accepted_deviation`，保留原阈值FAIL、原话/范围/版本哈希与独立审查，不能记成原精度通过，也不豁免强制要求。新增超范围误差需重新沟通。

先报告逐题配对差异、原始分子分母、评分分歧及预算；少量题只作描述。样本足够且设计成立再选配对统计方法、区间及多重比较校正，说明假设、题目族聚类和缺失处理，不用小样例算总体显著性。与范文重合度不作为正确率。

## 故障、恢复与证据留存

故障分类至少包含安装/依赖、宿主传输、身份/审批、资源路由、供应商未送达/真正未知、响应已收到但结构或证据引用不合法、有效FAIL/BLOCKED、数值/物理、产物/导出、超预算与用户取消。JSON Pointer错误不得记为网络故障；真正未知先只读对账，不盲重发。定向重跑有新运行身份，保留原失败，并绑定原请求/attempt、修复内容、预算及证据；不能择优替换主结果或循环复核刷PASS。

每单元保存原始输入及哈希、题目族/分层/暴露登记、冻结配置/提示词/代码/发行包身份、实际调用/usage、原始响应、受控执行与复跑证据、独立检查、用户真实决定、结果/图/论文及全页检查身份、外部两份评分和失败/恢复链。证据用独立新目录 `runs/evaluation/<campaign>/<unit>/`，不得覆盖 G 或旧评测；公开前单独脱敏和许可审查。原始数据、哈希和日志放证据附件，面向用户报告先给范围、带单位表格、实际代表图及完整文件链接，再列已接受偏差、检查状态、确认范围和局限。
