改模板正文只影响对应题目的样稿。当前 `resources/paper/bench-dragon-review.md` 是板凳龙专用模板，不能把换题名当作通用 Writer。外部 math-modeling/nature-figure 目录继续作为参考，项目内的政策和用户最新要求才是本项目实际默认值。

## 具体属于哪个阶段

| 阶段 | 本次补充 | 当前实际状态 |
|---|---|---|
| A+ 选法与证据规划 | 明确哪些时段、哪些物理细节、总览与局部图能解释题目，记录示意边界 | 当前小题六时刻方案已落实；其他题按需要制定 |
| B+ 交接与确认 | 正文通过与最终选图分别记录；新增备用图保留未变正文通过记录，换入文图重审 | 本次文件级真实用户正文确认与哈希已记录；通用数据库/API 写作确认尚未接入 |
| C+ 生成与检查 | 构造带真实尺寸的候选图，提供 Markdown 和讨论清单；每次加载项目默认配置，导出前阻断未确认稿 | 当前脚本/候选图/检查已实现；未新增正式论文导出器 |
| D5 | 三手复用上述入口，由论文手与临时独立质检执行写作流程；用户审阅与选图作为等待节点 | 后续实施，不宣称已在状态图上线 |
| E | 双确认后用同一中文稿套模板排版，实际编译、最终尺寸审图 | 后续实施；本次未导出正式论文 |

A+/B+/C+ 的本轮增强使用独立记录，不覆盖其原验收或旧数学包。先前正文通过和候选集记录继续保留。用户随后明确选择全部15张候选图，并在本次重执行中明确“补图后的新版正文也通过”；当前正文与选图双确认均已满足，不重复询问相同内容。

## 固定流程

理解题目→读取算法索引与匹配章节→确认模型/结果有效→规划证据与候选图→中文数学建模 Markdown→机械/数值/视觉检查→用户审阅正文并讨论图片→冻结最终正文与选图→正式排版、编译及最终审图。

当前已实现根目录约定、每次运行的上下文读取、单题脚本、文件级审阅记录和导出前检查函数。因此后续 Agent 有可追溯的默认入口，已有脚本也不依赖会话记忆；通用大模型 Writer、数据库写作审批及状态图自动等待/恢复仍属于后续 D5/B+ 集成工作，不能仅靠新增配置就宣称全部自动化。

## C+ 重执行入口

`python -m scripts.verify_cplus_writing --source <历史稿目录> --output <新复核目录> --qa-tools <本机Python审图工具目录>` 会读取当前写作规范、复制原稿和原图字节、复核真实数据与文件哈希、检查正文/选图分离确认、实际调用导出前门禁，并重新运行PDF字号/碰撞检查及Python审图渲染。该命令只沿用来源目录中的确认记录，不创造用户批准；本次随后到达的用户正文通过另存为 `manuscript-review.json` 与 `user-review-confirmed.json`，最终状态以 `review-status-confirmed.json` 为准。
